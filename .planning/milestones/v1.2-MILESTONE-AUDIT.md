### Integration Issues (Non-Blocking)

**INT-01 (Medium):** `traverse_graph()` SQL function does not return `source_type` or `source_id` columns. In `_find_graph_results()` (linking.py:455), source-backed graph entities fall back to graph node UUIDs which don't match source records. Result: graph-discovered Tickets, PRs, Slack threads appear in synthesis with empty titles/snippets. The graph signal still contributes to scoring but the LLM receives no content for these items.
- **Affects:** RETR-01, SYNTH-01, SYNTH-02 (data quality degradation, not functional breakage)
- **Fix:** Add source_type/source_id to traverse_graph() RETURNS TABLE, or add secondary GraphNode lookup

**INT-02 (Low):** Decision node snippet in linking.py reads `props.get('by')`, `props.get('source')`, `props.get('affects')` but persist_decision() stores different property keys. Person, source, and ticket info are in edges, not node properties. Decision snippets show "Unknown" for these fields.
- **Affects:** DECIDE-02, SYNTH-01 (display quality only)
- **Fix:** Denormalize into Decision node properties, or perform edge lookups for Decision nodes

**INT-03 (Info):** Duplicated `_compute_fingerprint()` in llm_extractor.py copies graph_ops logic. Currently consistent but creates divergence risk.
