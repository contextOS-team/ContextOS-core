# Phase 45 - UI Design Contract

> Visual and interaction contract for the missed-decision review surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | new-york, neutral base, Tailwind v4 CSS variables |
| Component library | Radix through existing shadcn primitives; custom dashboard pulse components for the review surface |
| Icon library | lucide for disclosed menus or secondary utility actions only; prefer text labels for primary review actions |
| Font | Geist Sans for dashboard UI, Geist Mono for source IDs, ticket/PR IDs, provider chips, and numeric confidence metadata |

Source of truth: `apps/web/components.json`, `apps/web/src/app/globals.css`, `apps/web/src/app/dashboard/pulse/*`, `apps/web/src/app/dashboard/chrome/*`, and the Phase 41 dashboard pulse direction.

## Phase Screen Contract

| Surface | Contract |
|---------|----------|
| Primary screen | Dashboard home pulse surface after source sync completion. |
| First viewport hierarchy | The existing headline remains the first focal point, `Recent decisions` remains the primary trusted-memory section, and exceptional missed-decision candidates appear as a bounded `Review exceptions` section in the right rail above `Active context` / `Needs you`. On mobile, `Review exceptions` appears after `Recent decisions` and before `Active context`. |
| Section visibility | Hide `Review exceptions` entirely when there are no open exception candidates. Do not render a celebratory empty card. |
| Section label | `Review exceptions` |
| Section support copy | `ContextOS auto-saves clear decisions. These need confirmation.` |
| Item count | Show top 3 suggestions by priority/confidence on the dashboard. Hard cap at 5 only if Phase 44 exposes a compact ranking API and the right rail still fits without pushing `Recent decisions` below the first viewport on desktop. |
| Focal point inside item | The inferred decision sentence is the row title. The exact source quote is the proof anchor below it. Confidence, people, affected system, and source chips are secondary metadata. |
| Relationship to Recent decisions | Never place missed-decision candidates inside `Recent decisions`. Only confirmed Decision nodes / Decision Receipts belong there. |
| Relationship to Phase 44 | Reuse the generic suggestion surface and statuses from Phase 44. Phase 45 may add candidate-specific rendering but must not create a second dashboard queue. |
| Out-of-scope UI | No full review page unless Phase 44 already shipped it. No task/doc/PR-comment creation controls. No autonomous action controls. No chat prompt or search bar. |

## User Flow Contract

| Step | Contract |
|------|----------|
| Sync completes | If the scanner finds candidates that are not safe to auto-save, the dashboard shows `Review exceptions` on the next data refresh. Provider sync success must not visually depend on scanner success. |
| User scans candidate | Row shows decision title, quote, source chip, confidence tier, people, affected system/workstream, and possible existing match. |
| No existing match | Primary action is `Save as new decision`. Secondary actions are `Defer` and `Dismiss candidate`. |
| Useful existing match | Primary action is `Add as evidence`. Secondary actions are `Save as new decision`, `Defer`, and `Ignore duplicate`. |
| Strong duplicate without new value | Candidate is suppressed automatically and never appears on the dashboard. |
| Confirmed outcome | Successful `Save as new decision` creates or updates trusted decision memory first, then resolves the suggestion. The UI may show a toast: `Saved as decision receipt.` |
| Evidence outcome | Successful `Add as evidence` attaches the quote/source/rationale to the existing artifact and resolves the suggestion. The UI may show a toast: `Added evidence to the existing decision.` |
| Defer outcome | Row resolves from the dashboard and can reappear after the Phase 44 snooze/defer window. Toast: `Deferred from review.` |
| Reject/ignore outcome | `Dismiss candidate` or `Ignore duplicate` requires confirmation before finalizing the lifecycle transition. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/text gaps, marker offsets, source chip internal gaps |
| sm | 8px | Compact metadata groups, chip gaps, row-title-to-proof spacing |
| md | 16px | Default row padding, button group gaps, skeleton spacing |
| lg | 24px | Section rhythm, review row vertical padding, right-rail section separation |
| xl | 32px | Dashboard grid gutters and expanded evidence spacing |
| 2xl | 48px | Major dashboard breaks only; avoid inside the right rail |
| 3xl | 64px | Page-level spacing outside this section only |

Exceptions: Fixed-format interactive targets may use 40px minimum height for desktop buttons and 44px on touch breakpoints. These are accessibility exceptions and remain multiples of 4.

## Typography

Declare exactly four size roles and two weights for new Phase 45 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata | 12px | 400 | 1.35 |
| Body | 14px | 400 | 1.5 |
| Row title | 16px | 600 | 1.35 |
| Section heading | 20px | 600 | 1.25 |

Rules:
- Use `text-wrap: balance` for the section heading and `text-wrap: pretty` for source-proof body copy.
- Use `font-variant-numeric: tabular-nums` for confidence percentages, source counts, time deltas, and sync-related counts.
- Keep `letter-spacing: 0` for all dashboard text. Do not add uppercase tracked labels.
- Use Geist Mono only for identifiers such as `Slack #eng`, `PR #418`, `Linear RD-781`, source IDs, and confidence numerals when grouped with IDs.
- Do not introduce additional font weights. Existing dashboard utilities may remain, but new missed-decision components use only 400 and 600.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / dark `oklch(0.105 0.012 270)` | Dashboard page background and negative space |
| Secondary (30%) | `var(--pulse-panel)` / `rgba(255,255,255,0.035)` | `Needs review` list panel, suggestion rows, source/evidence chips |
| Accent (10%) | `var(--primary)` / dark `oklch(0.70 0.135 168)` | 1px new-suggestion marker, focus-visible ring, real sync/scanner progress fill, and primary action emphasis for `Save as new decision` only |
| Destructive | `var(--destructive)` / dark `oklch(0.65 0.2 25)` | Confirmed destructive states, reject/ignore confirmation warning text, failed action error copy |

Accent reserved for: 1px new-suggestion marker, focus-visible ring, real progress fill, active navigation inherited from the dashboard, and the `Save as new decision` primary action.

Accent must not be used for every link, every hover state, card borders, confidence badges, secondary actions, row backgrounds, or decorative glows. Confidence tiers should use text and neutral chip hierarchy, not extra semantic colors.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Save as new decision |
| Secondary CTA | Add as evidence |
| Empty state heading | No review exceptions |
| Empty state body | ContextOS auto-saved clear decisions. Unclear or duplicate-looking candidates will appear here with the original source quote. |
| Error state | Could not load missed-decision suggestions. Refresh the dashboard or open Activity to confirm the source sync completed. |
| Destructive confirmation | Ignore duplicate: Keep the existing decision and hide this candidate. Dismiss candidate: Dismiss this candidate without creating decision memory. |

Additional copy rules:
- User-facing labels must use `Add as evidence`, `Ignore duplicate`, and `Save as new decision`; do not expose `Link existing`.
- Use `source quote`, `decision receipt`, `evidence`, `confidence`, and `affected system` consistently.
- Avoid hype language such as `AI found this`, `unlock`, `supercharge`, `magic`, or `autopilot`.
- Do not say a decision is confirmed until the user completes `Save as new decision` or `Add as evidence`.
- Error copy must always include a path forward: refresh, retry the action, or inspect Activity/source sync status.

## Component Contracts

| Component | Contract |
|-----------|----------|
| `NeedsReviewSuggestions` | Right-rail exception section using the existing `pulse-surface` token system. No wrapper card around the whole dashboard section beyond the bounded list panel. Hidden when empty. |
| `MissedDecisionSuggestionRow` | Dense row, radius 8px max, background `var(--pulse-panel)`, no decorative shadow beyond existing pulse list treatment. Title first, quote second, metadata third, actions last. |
| Source quote block | Required for every user-visible candidate. Use a 1px neutral left rule and two-line clamp by default. If the candidate lacks quote/source link, it must not surface in this section. |
| Source/evidence chips | Neutral chips with provider/source label and optional timestamp or count. Examples: `Slack thread - 14 messages`, `Notion page`, `Fathom transcript`, `Telegram chat`, `PR #418`. |
| Confidence metadata | Render as neutral text or chip: `high confidence` or `very high confidence`. Include a tooltip or title only if the exact scoring explanation is available. No colored risk scale. |
| Existing match preview | For weak matches, show one compact line: `Possible existing decision: {title}` with actions `Add as evidence` and `Save as new decision`. Do not call the action `Link existing`. |
| Action controls | Text buttons, not icon-only buttons. Primary action has the strongest visual weight. Secondary actions are neutral. Overflow menu is allowed for `Defer`, `Ignore duplicate`, and `Dismiss candidate` if the row becomes crowded. |
| Confirmation dialog | Use shadcn `alert-dialog` for `Ignore duplicate` and `Dismiss candidate`. Dialog buttons must be specific: `Keep candidate`, `Ignore duplicate`, `Dismiss candidate`. |
| Loading state | Use 2-3 compact skeleton rows under the `Needs review` label only while suggestions are loading. Do not animate list entry on page load. |
| Resolved state | On successful action, resolve the row with a short pending state and remove it from the list. If the API fails, keep the row and show inline error copy. |

## State And Data Contract

| State | UI Contract |
|-------|-------------|
| No open exceptions | Section absent. Dashboard rhythm closes naturally; `Recent decisions` remains lead. |
| Suggestions loading | Label plus neutral skeleton rows. Skeletons use existing shadcn `skeleton` and do not imply decisions exist. |
| Scanner pending after sync | If exposed, show one neutral line: `Checking recent sources for missed decisions.` Use progress only if backed by real scanner progress. No spinner. |
| Candidate surfaced | Show only if it has exact source quote/passage, inferred decision, inferred rationale, source link, and workspace-scoped suggestion state. |
| Candidate deferred | Optimistically remove after API success. If Phase 44 returns a snooze date, toast `Deferred until {date}.` |
| Candidate rejected | Requires confirmation, then remove after API success. |
| Candidate confirmed | Toast `Saved as decision receipt.` and remove after API success. Do not also create task/doc UI in this phase. |
| Candidate linked as evidence | Toast `Added evidence to the existing decision.` and remove after API success. |
| Candidate suppressed | Never user-visible. |
| Action error | Inline row error: `Could not update this suggestion. Try again.` Keep all actions available after failure. |

Workspace isolation is a UI requirement: fetches and mutations must use the active workspace context, and no row should render if its workspace does not match the selected workspace.

## Motion And Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Page load | No section entrance animation, no stagger, no scroll reveal. The dashboard is opened frequently and should feel immediate. |
| Row hover | Background-color transition only, 160ms, gated behind `@media (hover: hover) and (pointer: fine)`. |
| Button press | `transform: scale(0.96)` for action buttons, 100-120ms, `cubic-bezier(0.23, 1, 0.32, 1)`. Do not scale the full row. |
| Popover/menu | Scale/opacity from `scale(0.97)` with origin from trigger when using Radix. Duration 125-180ms. |
| Confirmation dialog | Center-origin opacity/scale from `scale(0.97)`, 180-220ms. Dialogs are not trigger-origin popovers. |
| Row resolve | Pending state changes background and opacity for 120-160ms. On success, remove row after data refresh or transition opacity/translateY by at most 4px for 160ms. |
| Keyboard actions | No motion beyond focus ring. Enter/Space should not trigger delayed animation. |
| Reduced motion | Remove transform movement. Keep color and opacity transitions only when they aid comprehension. |

Storyboard for the only allowed multi-step interaction:

| Time | Stage | Contract |
|------|-------|----------|
| 0ms | User presses action | Button scales to 0.96; row stays stable. |
| 100ms | API pending | Button returns to 1.0; row shows neutral pending copy such as `Saving...` or `Adding evidence...`. |
| 160ms | Success | Toast appears; row resolves from the visible list. |
| Failure | API error | Row remains, inline error appears, and focus returns to the failed action. |

Animation rules:
- Never use `transition: all`.
- Use CSS transitions or WAAPI for small programmatic effects; do not add Motion/Framer Motion for this section.
- Do not animate `height`, `padding`, `margin`, or layout properties.
- Use `will-change` only if a measured first-frame stutter appears, and only for `transform` or `opacity`.

## Accessibility Contract

| Area | Contract |
|------|----------|
| Hit area | All action buttons and menu triggers are at least 40px high on desktop and 44px on touch breakpoints. |
| Labels | No icon-only primary actions. Overflow menus must have accessible names such as `More actions for missed decision`. |
| Focus | Use the global tokenized focus ring. Do not remove outline. |
| Live regions | Action success and failure toasts use polite announcements. Do not use assertive announcements for routine review actions. |
| Dialogs | `Ignore duplicate` and `Dismiss candidate` confirmations use `alert-dialog` semantics and return focus to the triggering control on close. |
| Source quote | Preserve quote text as real text, not canvas/SVG. Line clamp must not remove the full quote from accessible text if an expansion is provided. |
| Color dependence | Confidence and lifecycle state must be readable from text, not color alone. |
