<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source text to LLM extractor | Untrusted Slack/Telegram/Fathom/Notion content enters prompt construction. |
| LLM output to database | Model-generated candidate fields become durable records only after validation. |
| Dedupe across artifacts | Candidate matching reads graph, suggestions, tickets, docs, PRs, and embeddings. |
| Candidate to suggestion | Detection output becomes user-visible review state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-02-01 | Tampering | LLM extraction prompt | mitigate | Treat source text as untrusted, include prompt-injection guardrails, and require exact source quote validation before persistence. |
| T-45-02-02 | Tampering | Candidate validation | mitigate | Drop candidates missing source quote, inferred decision, inferred rationale, or source link; never surface `needs_review` by default. |
| T-45-02-03 | Information Disclosure | Dedupe lookups | mitigate | Every graph, embedding, suggestion, ticket, doc, and PR lookup must filter by `workspace_id`. |
| T-45-02-04 | Denial of Service | Duplicate/suggestion spam | mitigate | Apply quote fingerprint, normalized decision fingerprint, semantic match, and graph-neighborhood tie-breaker before publishing suggestions. |
| T-45-02-05 | Repudiation | Suppressed/linked candidates | mitigate | Persist suppression reason, matched entity type/id, scan run ID, and evidence metadata on the candidate record. |
| T-45-SC | Tampering | Package installs | accept | No package-manager install tasks are planned; use existing `rapidfuzz`, embeddings, graph, and LLM client code. |
</threat_model>
