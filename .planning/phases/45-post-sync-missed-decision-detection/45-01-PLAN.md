<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Provider sync to scanner enqueue | Provider sync success crosses into optional missed-decision background work. |
| Source tables to scan windows | Sensitive workspace source text is selected for later LLM processing. |
| Browser/user to database | RLS must protect new persisted scan and candidate records. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01-01 | Information Disclosure | `missed_decision_*` tables | mitigate | Add `workspace_id` to every table, RLS policies through `workspace_members`, and workspace predicates in every source loader. |
| T-45-01-02 | Denial of Service | First scan source window | mitigate | Bound first scans to `max(source_connected_at, now - 14 days)` and limit source batches; never scan full workspace history by default. |
| T-45-01-03 | Denial of Service | Provider sync completion | mitigate | Enqueue scans in a savepoint/fail-silent helper so scanner errors cannot rollback or mark provider sync failed. |
| T-45-01-04 | Repudiation | Scan run observability | mitigate | Persist scan run status, attempts, counts, source window, started/completed timestamps, and error message for retry/audit. |
| T-45-01-05 | Tampering | Scan checkpoint updates | mitigate | Only update `last_missed_decision_scan_at` after a successful scan run transaction; failed runs preserve the prior checkpoint. |
| T-45-SC | Tampering | Package installs | accept | No package-manager install tasks are planned; this plan uses existing Supabase, SQLModel, pytest, and provider code. |
</threat_model>
