  <action>
Create a centralized, Laminar-instrumented LLM client:

1. **backend/src/services/llm_client.py**:
   - Import `observe` and `set_laminar_metadata` from `src.observability.laminar`
   - Create `LLMClient` class:
     - Constructor accepts optional `model_name: str = "gemini-2.0-flash"` (default model per project decision to use google-genai)
     - Uses `google.genai` SDK (already in dependencies as `google-genai`)
     - `@observe(name="llm_generate")` decorator on the main generation method
     - `async def generate(self, prompt: str, system_prompt: str | None = None, workspace_id: UUID | None = None, ticket_identifier: str | None = None) -> LLMResponse`:
       - Call `set_laminar_metadata(workspace_id, ticket_identifier)` if provided
       - Call Google GenAI API: `client.models.generate_content(model=self.model_name, contents=prompt, config=GenerateContentConfig(system_instruction=system_prompt))`
       - Capture: response text, token counts (prompt_tokens, completion_tokens from usage_metadata), latency (time.monotonic before/after)
       - Return `LLMResponse` dataclass with: `text`, `prompt_tokens`, `completion_tokens`, `total_tokens`, `latency_ms`, `model`
     - `@observe(name="llm_generate_with_context")` on a convenience method:
       - `async def generate_context_page(self, ticket_data: dict, sources: list[dict], workspace_id: UUID, ticket_identifier: str) -> LLMResponse`:
       - Builds the synthesis prompt from ticket data and sources (placeholder template for Phase 4 to fill in)
       - Calls `self.generate()` with the composed prompt
       - Tags trace with workspace_id and ticket_identifier

   - Create `LLMResponse` dataclass:
     ```python
     @dataclass
     class LLMResponse:
         text: str
         prompt_tokens: int
         completion_tokens: int
         total_tokens: int
         latency_ms: float
         model: str
     ```

   - Create module-level factory function:
     - `def get_llm_client() -> LLMClient` (cached singleton pattern)

2. **Update backend/src/main.py**:
   - In the lifespan startup, call `init_laminar(settings)` (import from observability.laminar)
   - This ensures Laminar is initialized before any LLM client is used
   - If observability/__init__.py was created by 06-02, just add the laminar init call alongside sentry init

Note: Phase 4 (Context Generation by Dulat) will use this `LLMClient` directly. The client is designed so ALL LLM calls automatically get Laminar tracing without the caller needing to think about observability.

Note: The `google-genai` package is the new Google Gen AI SDK. Import as `from google import genai`. The `generate_content` method is on `genai.Client().models.generate_content()`. Use the async version `genai.Client().aio.models.generate_content()` for async context.
