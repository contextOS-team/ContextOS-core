  <action>
Create a Chrome Manifest V3 extension configuration:

1. **manifest.json** in `apps/web/public/`:
   - `manifest_version: 3`
   - `name: "ContextOS"`, `version: "0.1.0"`
   - `description: "Quick context for Linear tickets"`
   - `permissions: ["activeTab", "storage"]`
   - `host_permissions: ["https://linear.app/*"]`
   - `action.default_popup: "extension/popup.html"`
   - `action.default_icon`: 16, 48, 128px icon references
   - `background.service_worker: "extension/background.js"` (type: module)
   - `content_scripts`: match `https://linear.app/*`, run `extension/content.js`

2. **content.ts** -- Content script injected on Linear pages:
   - Extract Linear ticket identifier from URL using regex pattern: `/linear\.app\/[^/]+\/issue\/([A-Z]+-\d+)/`
   - On page load and URL change (listen for `popstate` and observe URL mutations via MutationObserver on `document.title`), send message to background with `{ type: "TICKET_DETECTED", identifier: "ENG-123" }` or `{ type: "NO_TICKET" }`
   - Handle SPA navigation (Linear is a SPA -- URL changes without full page loads)

3. **background.ts** -- Service worker:
   - Listen for messages from content script
   - Store current ticket identifier in `chrome.storage.local`
   - Listen for popup connection and respond with current ticket context
   - Expose a function `fetchContextPage(identifier: string, token: string)` that calls `GET {BACKEND_URL}/api/context/by-ticket/{identifier}` with Authorization header
   - Store BACKEND_URL in chrome.storage.sync (configurable, defaults to `http://localhost:8000`)

Note: The actual context page API endpoint does not exist yet (Phase 4/5 builds it). For now, the extension code should call the endpoint and gracefully handle 404 responses with a "Context not yet generated" message. This ensures the extension is ready to work once the backend endpoint exists.

Create the extension popup that displays context page content:

1. **popup.html** -- Entry point for the popup:
   - Basic HTML shell loading popup.js and styles.css
   - Root div for React mounting
   - Link to styles.css

2. **styles.css** -- Tailwind-inspired utility styles (standalone, NOT importing full Tailwind since extension popup is separate from Next.js build):
   - Base reset styles
   - Card, heading, section, loading, error, empty-state utility classes
   - Keep it minimal (~50 lines) -- just enough for a clean popup

3. **popup.tsx** -- React popup component:
   - On mount: get current ticket from `chrome.storage.local`
   - If no ticket detected: show "Navigate to a Linear ticket to see context"
   - If ticket detected: show loading spinner, then call background service worker to fetch context
   - On success: render context page content in 5 sections (origin story, business requirements, technical decisions, related work, AI prompt) with section headers and formatted markdown
   - On 404/no context: show "No context page generated yet for {TICKET-ID}" with a note to generate from dashboard
   - On auth error (401): show "Please log in to ContextOS first" with link to dashboard
   - On network error: show "Cannot reach ContextOS backend" with retry button
   - Popup dimensions: width 400px, max-height 600px with scroll
   - Include a small header with ContextOS logo text and the ticket identifier
   - Include a "Open in Dashboard" link at the bottom that opens `{APP_URL}/dashboard/context/{ticket-id}`
   - Auth: read Supabase session token from `chrome.storage.local` (set by user logging in via dashboard). For now, include a simple token input field in a settings section (gear icon) where users paste their API token.

Note: Use vanilla DOM manipulation or a lightweight approach rather than full React for the popup to keep bundle size small. If using React, the popup must be pre-built (not using Next.js build pipeline). Alternatively, implement as a plain TypeScript file that manipulates DOM directly -- this is simpler for an extension popup.
