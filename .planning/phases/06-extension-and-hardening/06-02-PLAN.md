Create observability and middleware packages:

1. **backend/src/observability/sentry.py** -- Sentry SDK initialization:
   - `init_sentry(settings)` function that calls `sentry_sdk.init()`:
     - `dsn=settings.SENTRY_DSN` (no-op if empty string)
     - `integrations=[FastApiIntegration(), SqlalchemyIntegration()]`
     - `traces_sample_rate=0.2` in production, `1.0` in dev (Claude's discretion on exact rates)
     - `profiles_sample_rate=0.1` in production
     - `environment=settings.ENVIRONMENT.value`
     - `release=f"contextos-backend@{version}"` (read from pyproject.toml or hardcode "0.1.0")
     - `send_default_pii=False` (privacy)
   - `set_sentry_context(workspace_id, user_id, endpoint)` helper that calls:
     - `sentry_sdk.set_tag("workspace_id", str(workspace_id))`
     - `sentry_sdk.set_tag("user_id", str(user_id))`
     - `sentry_sdk.set_tag("endpoint", endpoint)`
     - `sentry_sdk.set_user({"id": str(user_id)})`
   - Create a FastAPI middleware class `SentryContextMiddleware` that:
     - On each request, if user is authenticated (check for auth header), extract user context and call `set_sentry_context`
     - Uses `sentry_sdk.configure_scope()` to set tags per-request
     - Does NOT block on auth failures -- just tags what's available

2. **backend/src/observability/logging.py** -- Structured JSON logging:
   - Use `structlog` library (add to pyproject.toml dependencies)
   - `configure_logging(environment)` function that:
     - In production: JSON renderer (`structlog.processors.JSONRenderer`)
     - In dev: console renderer with colors (`structlog.dev.ConsoleRenderer`)
     - Add processors: `add_log_level`, `TimeStamper(fmt="iso")`, `StackInfoRenderer`
     - Bind `correlation_id` from context var (set by correlation middleware)
   - `get_logger(name)` function returning a bound structlog logger
   - Use `contextvars.ContextVar` for correlation_id propagation

3. **backend/src/middleware/correlation.py** -- Correlation ID middleware:
   - `CorrelationIdMiddleware` (Starlette BaseHTTPMiddleware):
     - On request: read `X-Correlation-ID` header or generate UUID4
     - Set correlation ID in contextvars.ContextVar
     - Add `X-Correlation-ID` response header
     - Log request start and completion with method, path, status, duration

4. **backend/src/middleware/rate_limit.py** -- Rate limiting:
   - Use in-memory token bucket (no Redis dependency for MVP -- per user decision that FastAPI background tasks suffice, keeping infra simple)
   - `RateLimitMiddleware` that:
     - Only applies to paths matching: `/api/webhooks/*`, `/api/linear/callback`, `/api/slack/callback`, `/api/fathom/*`
     - Default: 60 requests/minute per IP
     - Webhook endpoints: 120 requests/minute per IP (higher for legitimate webhook bursts)
     - Returns 429 Too Many Requests with `Retry-After` header when exceeded
   - Simple dict-based sliding window: `{ip: [(timestamp, count)]}` with cleanup on access
