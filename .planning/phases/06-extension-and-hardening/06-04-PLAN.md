1. **Update backend/src/services/vault.py**:
   - Keep existing `token_name()`, `store_token()`, `read_token()`, `delete_token()` functions
   - Add `read_token_with_lazy_migrate(session, name, plaintext_value)` function:
     - First try `read_token(session, name)` from Vault
     - If found: return the Vault value
     - If not found AND `plaintext_value` is not None/empty: store it in Vault via `store_token(session, name, plaintext_value)`, then return it
     - If not found AND no plaintext: return None
     - This enables seamless migration: old rows with plaintext values get migrated on first read
   - Add `check_vault_health(session) -> bool` function:
     - Store a test secret, read it back, delete it, return True
     - On any exception, return False
     - Used by deep health endpoint

2. **Verify backend/src/services/linear_oauth.py** already uses Vault:
   - Linear OAuth was built in Phase 2 with Vault storage -- token values in DB are Vault secret name references, not actual tokens
   - Confirm the pattern: on callback, tokens stored via `vault.store_token()`, on read, tokens fetched via `vault.read_token()`
   - If any direct DB token column access exists (reading `oauth_token.access_token` as a real token), replace with `vault.read_token()` call
   - The DB column `access_token` already stores the Vault secret NAME (e.g., "oauth_linear_{uuid}_access"), so reading from Vault using that name is the correct pattern

3. **Verify backend/src/services/slack_oauth.py** uses Vault:

     - Each check returns: `{ status: "ok" | "degraded" | "unreachable", latency_ms: number }`
     - Overall status: "healthy" if DB + Vault are ok (external APIs can be degraded)
     - Return all check results as JSON:
       ```json
       {
         "status": "healthy",
         "checks": {
       ```
