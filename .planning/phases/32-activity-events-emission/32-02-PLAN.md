  <action>
Add `from src.services.sync_adapter import emit_activity` to each file and inject emit calls at these specific points:

**1. Linear ticket_created** (`linear_webhook.py`):
- In the issue create handler (look for function handling `action == "create"` for issues, likely `handle_issue_create()` or similar)
- After the ticket is synced/upserted successfully, emit:
  ```python
  await emit_activity(session, workspace_id, "ticket_created", metadata={
      "integration": "linear",
      "ticket_id": ticket.identifier,  # e.g. "CON-52"
      "title": ticket.title,
  })
  ```
- Only emit for NEW issues (action == "create"), NOT updates or status changes

**2. Jira ticket_created** (`jira_webhook.py`):
- In the issue created handler (look for `_handle_issue_created()` or `issue_created` action)
- After the issue is upserted, emit:
  ```python
  await emit_activity(session, workspace_id, "ticket_created", metadata={
      "integration": "jira",
      "ticket_id": issue.jira_key,  # e.g. "PROJ-123"
      "title": issue.summary,
  })
  ```

**3. GitHub pr_merged** (`github_webhook.py`):
- In the pull request handler (look for `handle_pull_request_event()` or similar)
- ONLY when the PR is merged: check `action == "closed"` AND `pr_data.get("merged") == True` (or check the computed `state == "merged"` if the code already maps PR state)
- After the PR record is upserted, emit:
  ```python
  await emit_activity(session, workspace_id, "pr_merged", metadata={
      "integration": "github",
      "pr_number": pr_record.number,
      "title": pr_record.title,
      "repo": repo_full_name,
  })
  ```
- Do NOT emit for closed-but-not-merged PRs

**4. GitLab pr_merged** (`gitlab_webhook.py`):
- In the merge request handler (look for `_handle_merge_request_event()` or similar)
- ONLY when state is "merged" (check the computed state or `attrs.get("state") == "merged"`)
- After the MR record is upserted, emit:
  ```python
  await emit_activity(session, workspace_id, "pr_merged", metadata={
      "integration": "gitlab",
      "pr_number": mr_record.iid,
      "title": mr_record.title,
      "repo": project_path,
  })
  ```

**5. Fathom meeting_recorded** (`fathom.py`):
- In `poll_transcripts()`, after each NEW transcript is successfully ingested
- Emit:
  ```python
  await emit_activity(session, workspace_id, "meeting_recorded", metadata={
      "title": title,
      "duration_minutes": duration_minutes,
      "participants_count": len(participant_names) if participant_names else None,
  })
  ```
- Note: Fathom's poll_transcripts may not have a session parameter directly -- check the function signature. If it creates its own session, use that session. If it doesn't use SQLAlchemy sessions (uses Supabase client instead), create a minimal session for the emit call or use the available database connection.

**6. Notion page_created** (`notion_webhook.py` and/or `notion_sync.py`):
- Notion webhooks only fire `page.content_updated`, not create. Two approaches:
  a. In the webhook handler: check if the page existed in DB before the sync call. If it was newly inserted (not an update), emit `page_created`.
  b. In `notion_sync.py` during `run_full_sync()`: when inserting a new page (vs updating existing), emit `page_created`.
- Use approach (b) since it's more reliable. In `notion_sync.py`, find where pages are bulk-upserted and detect new insertions (e.g., pages not previously in the DB):
  ```python
  await emit_activity(session, workspace_id, "page_created", metadata={
      "integration": "notion",
      "page_title": page.title,
  })
  ```
- Emit per-page only for truly new pages during full sync. If this creates too many events, limit to the first 5 new pages per sync.

**All webhook emissions must:**
- Use the EXISTING session from the handler (never create a new one)
- Be fail-silent (emit_activity handles this)
- Be placed AFTER the data is successfully processed (not before)

  <action>
Add `from src.services.sync_adapter import emit_activity` to each router file and inject emit calls.

**OAuth providers** (Linear, GitHub, GitLab, Notion, Slack, Jira):
- In the `callback()` endpoint (OAuth code exchange handler):
  - AFTER the OAuth exchange succeeds (code exchanged for token, integration record created)
  - BEFORE the redirect response is returned
  - The endpoint has `session: AsyncSession = Depends(get_session)` available
  - Emit:
    ```python
    await emit_activity(
        session, workspace_id, "integration_connected",
        metadata={"integration": "{provider_name}"},
        actor_id=user_id,
    )
    ```
  - Extract `workspace_id` and `user_id` from the auth context already available in the callback

**API key / bot token providers** (Fathom, Telegram):
- In the `connect()` endpoint:
  - AFTER the connection/validation succeeds
  - BEFORE the response is returned
  - Emit same pattern as above with the provider name

**All 7 providers -- disconnect endpoint:**
- In the `disconnect_{provider}()` or equivalent endpoint:
  - AFTER the disconnect service call succeeds
  - BEFORE the response is returned
  - Emit:
    ```python
    await emit_activity(
        session, workspace_id, "integration_disconnected",
        metadata={"integration": "{provider_name}"},
        actor_id=user.user_id,  # or however user_id is accessed in that router
    )
    ```

**Important:**
- Each router already has a session dependency -- use it, don't create a new one
- Some callbacks may commit the session before the redirect. If so, the emit_activity call should go BEFORE that commit, or accept that it will be in a new implicit transaction (which is fine since emit_activity is fail-silent)
- Provider names must match exactly: "linear", "github", "gitlab", "jira", "notion", "slack", "fathom", "telegram" -- these will be used by the frontend for icon coloring
- For connect events, include `actor_id` (the user who connected). For disconnect events, same.
- If the router uses `current_user` or similar dependency, extract `user_id` from it
