    - Test 3: parse_file() extracts function/class definitions from TypeScript code
    - Test 4: parse_file() returns empty list for binary or unparseable files (graceful handling)
    - Test 5: parse_file() includes decorators in the extracted content for decorated functions
    - Test 6: parse_file() extracts type/interface definitions from TypeScript
    - Test 7: detect_language() maps file extensions to tree-sitter language names correctly

  <action>
    **Dependencies (pyproject.toml):**
    Add `tree-sitter-language-pack` to project dependencies. This package provides pre-compiled wheels for 165+ languages with zero GPL deps. No need for individual language packages.

    **code_parser.py:**
    Create a parsing service using tree-sitter-language-pack:

    1. `detect_language(file_path: str) -> str | None` — Map file extensions to tree-sitter language names. Support at minimum: .py -> python, .ts/.tsx -> typescript, .js/.jsx -> javascript, .go -> go, .rs -> rust, .java -> java, .rb -> ruby, .cpp/.cc/.cxx -> cpp, .c/.h -> c. Return None for unknown extensions.

    2. `_get_parser(language: str) -> Parser` — Get or create a cached tree-sitter parser for the given language. Use tree-sitter-language-pack's `get_language()` and `get_parser()` functions. Cache parsers in a module-level dict to avoid re-initialization.

    3. `parse_file(file_path: str, content: str, language: str) -> list[CodeChunkData]` where CodeChunkData is a dataclass with fields: symbol_name, symbol_type, language, content, start_line, end_line, metadata (dict).

    Extraction logic by language family:
    - **Python**: Extract `function_definition`, `class_definition`, `decorated_definition` nodes. For decorated definitions, include the decorator in the content. For classes, also extract methods as separate chunks with symbol_type="method".
    - **TypeScript/JavaScript**: Extract `function_declaration`, `class_declaration`, `interface_declaration`, `type_alias_declaration`, `arrow_function` (only named, via `variable_declarator` parent), `method_definition`.
    - **Go**: Extract `function_declaration`, `method_declaration`, `type_declaration` (struct/interface).
    - **Other languages**: Extract `function_definition`, `class_definition` as a generic fallback using common tree-sitter node types.

    For each extracted chunk:
    - `content` = the full text of the node (including decorators, docstrings, type annotations)
    - `start_line` = node start row + 1 (tree-sitter is 0-indexed)
    - `end_line` = node end row + 1
    - `metadata` includes: `docstring` (if extractable), `parent_class` (for methods), `decorators` (list of decorator names)

    Skip chunks with content < 2 lines (trivial one-liners like `pass` stubs).

    **code_indexer.py:**
    Create the repo indexing orchestrator:

    1. `async def index_repo(workspace_id: UUID, repo_full_name: str, session: AsyncSession, settings: Settings) -> dict` — Main entry point:
       - Get installation token via `get_installation_token()`
       - Shallow clone the repo to a temp directory: `git clone --depth 1 --single-branch https://x-access-token:{token}@github.com/{repo_full_name}.git {tmp_dir}`
       - Use `asyncio.create_subprocess_exec` for the git clone (non-blocking)
       - Walk the cloned directory, skip hidden dirs (`.git`, `.venv`, `node_modules`, `__pycache__`, `.next`, `dist`, `build`), skip binary files (check first 512 bytes for null bytes)
       - For each source file: detect language, parse with tree-sitter, collect chunks
       - Upsert chunks into code_chunks table with content-hash dedup (same pattern as embedding service: compute hash, skip if unchanged)
       - Soft-delete code_chunks that no longer exist in the repo (file removed or symbol removed)
       - Clean up temp directory after indexing (use `tempfile.mkdtemp()` and `shutil.rmtree()` in a finally block)
       - Return summary dict: `{repo: repo_full_name, files_scanned: N, chunks_created: N, chunks_updated: N, chunks_deleted: N}`

    2. `async def index_workspace_repos(workspace_id: UUID, session: AsyncSession, settings: Settings) -> list[dict]` — Index all selected repos for a workspace:
       - Get selected repos from `get_cached_repos()` filtered by `is_repo_monitored()`
       - Index repos sequentially (per Phase 7 decision to avoid rate limit exhaustion)
       - Return list of per-repo summary dicts

    3. Helper `_should_skip_path(path: str) -> bool` for directory/file skip logic. Skip dirs: `.git`, `node_modules`, `__pycache__`, `.venv`, `venv`, `.next`, `dist`, `build`, `.tox`, `.mypy_cache`, `.pytest_cache`, `vendor`. Skip files: lockfiles (package-lock.json, yarn.lock, Pipfile.lock, poetry.lock), generated files (*.min.js, *.map, *.d.ts from declaration files -- actually keep .d.ts as they contain type defs), files > 500KB.

    Use standard logging throughout. Log at INFO level: repo clone start/finish, files scanned count, chunks created/updated/deleted. Log at WARNING: clone failures, parse failures. Log at DEBUG: individual file processing.
  </action>
