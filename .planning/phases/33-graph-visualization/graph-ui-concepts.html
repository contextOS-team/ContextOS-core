Graph Visualization — UI/UX Concepts

Phase 33 · ContextOS v1.3 Live Intelligence

Interactive knowledge graph explorer for ticket context. Nodes represent people, decisions, PRs, messages, code, and documents. The aesthetic: Neo4j Bloom meets Linear — glowing entity nodes on dark backgrounds with precise, minimal chrome.

01 — Entity Color Palette

Each entity type gets a distinct OKLCH color, tuned for equal perceptual brightness on dark backgrounds. Colors are used for node borders, icons, glow effects, and edge tinting.

04 — Edge Styles

Edges are subtle by default, becoming prominent on hover or when connecting to a selected node. Relationship types are distinguished by line pattern and subtle color tinting.

authored / created
Solid line, directional arrow. Person → Ticket/PR/Decision
mentions / references
Dashed line, directional. Message → Ticket, PR → Decision
blocks / depends_on
Thicker line, red-tinted. Shows critical dependencies
related_to (generic)
Thin, muted, no arrow. Low-confidence / semantic link
◆ Hover behavior: Hovering an edge reveals a floating label with the relationship type (e.g., "mentions") at the midpoint. Connected nodes brighten; unconnected nodes dim to 30% opacity. This focus effect makes individual relationships legible in dense graphs.

10 — Interaction Patterns Summary

Node Interactions

Click → Open detail panel
Hover → Highlight node + connected edges, dim others
Drag → Move node, edges follow (pin to position)
Double-click → Focus view: recenter + zoom to node's neighborhood
Right-click → Context menu: "Expand connections", "Navigate to source", "Pin/Unpin"

Canvas Interactions

Scroll → Zoom in/out (smooth, centered on cursor)
Click + Drag → Pan the canvas
⌘K → Open search (highlights matching nodes)
Esc → Close detail panel / deselect node
⌘0 → Fit all nodes in view
11 — Design Decisions Summary

Key design decisions captured for Phase 33 CONTEXT.md:

Visual Language
• 8 entity colors in OKLCH, perceptually equiluminant on dark backgrounds
• Three-tier semantic zoom: Full card → Pill → Glow dot
• Glow effects via color-mix box-shadows (not filters — better perf)
• Edges: solid/dashed/thick by relationship type, dim at rest, bright on hover
Interaction
• Click → right sidebar detail panel (never navigate away)
• Hover → highlight connected subgraph, dim rest to 30%
• Double-click → focus/recenter on node neighborhood
• Floating controls pill at bottom: zoom, layout, search, filter
Layout
• Three ELK modes: Organic (force), Grouped (compound), Radial (ego)
• Layout computed in Web Worker to keep UI responsive
• MiniMap component in bottom-right corner
• Progressive disclosure: start at depth 2, expand on demand
Placement
• Context detail page: Tab alongside markdown content ("Content" | "Graph")
• Standalone /dashboard/graph: Full-page with filter chips in topbar
• Same <GraphExplorer /> component in both, different container bounds
• Standalone page queries all workspace entities, not just one ticket
