**1. Create `backend/src/services/notion_sync.py`:**

Extract and refine the sync logic from the router's inline _run_sync function into a proper service module:

```python
"""Notion page sync orchestration.

Handles initial full-sync backfill and individual page re-sync for
webhook-triggered updates. Creates its own DB session for background
task isolation (same pattern as linear_webhook.py, slack_events.py).
"""
```

Functions:

`async def run_full_sync(workspace_id: UUID, user_id: UUID)`:
  - Create own session via `async_session()` for background task isolation
  - Read access token via `get_valid_access_token`
  - Create NotionClient with token
  - Fetch all pages via `client.get_all_pages()`
  - Update integration config: `{"sync_status": "syncing", "pages_total": len(pages)}`
  - For each page: call `sync_single_page(session, client, workspace_id, page_data)`
  - Collect all upserted page IDs into a list
  - Track count of synced pages
  - **Call `await embedding.queue_embedding_generation(session, workspace_id, "notion_page", page_ids_list)`** after all pages are upserted (same pattern as `linear_sync.py` which calls `from src.services import embedding` then `await embedding.queue_embedding_generation(...)`)
  - On completion: update config `{"sync_status": "complete", "last_sync_at": now_iso, "pages_synced": count}`
  - On error: update config `{"sync_status": "error", "sync_error": str(e)}`
  - Wrap in try/except with logging
  - Close session when done

Import at top of file: `from src.services import embedding`

`async def sync_single_page(session: AsyncSession, client: NotionClient, workspace_id: UUID, page_data: dict)`:
  - Extract page_id from page_data["id"] (remove hyphens if needed)
  - Extract title from page_data["properties"]["title"] (or Name, etc.) -- Notion pages have varying property names for title
  - Extract page URL from page_data["url"]
  - Extract parent info from page_data["parent"]
  - Extract last_edited_time from page_data["last_edited_time"] (Notion API field -> maps to DB column `notion_updated_at`)
  - Fetch full markdown: `content = await client.get_page_markdown(page_id)`
  - Upsert into notion_pages table using PostgreSQL upsert pattern (insert on_conflict_do_update on workspace_id + notion_id). Map API fields to DB columns: page_data["id"] -> notion_id, page_data["url"] -> url, page_data["last_edited_time"] -> notion_updated_at, raw API response -> raw_data, markdown content -> content
  - Return the upserted NotionPage record

`async def sync_page_by_id(workspace_id: UUID, user_id: UUID, notion_page_id: str)`:
  - Create own session
  - Read access token
  - Create NotionClient
  - Fetch page metadata via `client.get_page(notion_page_id)`
  - Call `sync_single_page(session, client, workspace_id, page_data)`
  - Call `await embedding.queue_embedding_generation(session, workspace_id, "notion_page", [page_record.id])` to regenerate embedding for the updated page
  - Commit and close session
  - Used by webhook handler for individual page re-sync

Helper: `def _extract_title(properties: dict) -> str`:
  - Look for "title" type property in properties dict
  - Extract plain_text from the title rich_text array
  - Fallback to "Untitled" if not found
  - Notion pages can have different property names containing the title -- iterate properties to find the one with type "title"

`async def process_notion_webhook_event(workspace_id: UUID, payload: dict)`:
  - Extract event type from payload (e.g., payload.get("type"))
  - For "page.content_updated" events:
    - Extract page_id from payload (e.g., payload.get("entity", {}).get("id") or payload.get("data", {}).get("id"))
    - Look up a user_id for the workspace (query WorkspaceMember for workspace_id, same pattern as OAuth callback)
    - Call `sync_page_by_id(workspace_id, user_id, page_id)`
    - Log: "Processed Notion page update: {page_id}"
  - For unrecognized events: log and skip
  - Wrap in try/except with error logging

**3. Add Notion webhook endpoint to `backend/src/routers/webhooks.py`:**

Add a new endpoint `POST /api/webhooks/notion` following the exact pattern of the GitHub webhook handler:

```python
@router.post("/notion")
async def receive_notion_webhook(
    request: Request,
    background_tasks: BackgroundTasks,
    session: AsyncSession = Depends(get_session),
) -> dict:
```

Implementation:
1. Read raw body bytes
2. Verify HMAC-SHA256 signature from `X-Notion-Signature` header:
   - Compute HMAC-SHA256 using the `verification_token` (stored per integration, or use NOTION_CLIENT_SECRET as signing key -- Notion uses the verification_token from webhook setup)
   - **IMPORTANT**: Notion webhook signature uses the `verification_token` that was provided during webhook subscription verification. Store this token in the workspace_integrations.config JSONB during webhook setup. For signature verification, read it from the integration config.
   - However, since webhook subscription is done manually in Notion's UI (per CONTEXT.md -- "Webhook setup requires SSL endpoint + verification flow via Notion dashboard"), the verification_token needs to be stored when the user completes webhook setup.
   - **Pragmatic approach**: Use `NOTION_CLIENT_SECRET` as the HMAC key initially. If Notion uses a different signing key, it can be reconfigured. Check the X-Notion-Signature header computation: `hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()`
   - Actually per the Notion docs: the signature is computed using the `verification_token` (the one Notion sends during verification). Since this is per-integration, we need a different approach: store the verification_token per workspace in the config JSONB and look it up from the webhook payload (which includes the entity workspace info).
   - **Simplest correct approach**: Add a `NOTION_WEBHOOK_SECRET` setting to config.py. The user sets this to match the verification_token from Notion webhook setup. Use this for all HMAC verification (same pattern as LINEAR_WEBHOOK_SECRET).
3. Parse JSON payload
4. Generate a delivery_id from payload data (or use a hash of the payload) for idempotency since Notion may not provide a delivery header. Use a combination of event type + entity_id + timestamp as the delivery key.
5. Check WebhookDelivery for duplicate
6. Record delivery
7. Determine workspace from the Notion workspace_id in the payload by looking up WorkspaceIntegration where external_id matches
8. Delegate to background task: `process_notion_webhook_event(workspace_id, payload)`
9. Return `{"status": "accepted"}`

Also handle the initial verification flow: when Notion first sends a verification request, it may send a different payload structure. Check if the payload contains a `verification_token` field -- if so, log it and return 200 (the user needs to copy this token into Notion's UI).
