<decisions>
## Implementation Decisions

### Data Scope
- Ingest **pages and databases** -- skip standalone comments
- Recursively traverse **full depth** of nested page hierarchies under user-selected pages
- Store **full page content** converted to markdown (not just metadata)
- Notion blocks (paragraphs, headings, code, lists, etc.) flattened to clean markdown for search and AI synthesis
- Generate **embeddings during initial sync** (same pattern as Linear tickets, Slack messages)

### OAuth & Access Control
- Notion OAuth 2.0 with public integration flow
- Users select which pages/databases to share **during OAuth** (Notion's native page picker)
- Access tokens + refresh tokens stored in Vault (existing pattern)
- HMAC-SHA256 signed state parameter for CSRF protection (existing pattern)
- To update shared pages, users go to **Notion's integration settings** (no custom picker needed in ContextOS)

### Sync Strategy
- **Webhooks** for real-time updates (Notion's native HMAC-SHA256 signed webhooks)
  - Subscribe to `page.content_updated` events (aggregated, ~1 min batching by Notion)
  - Signature verification via `X-Notion-Signature` header using `verification_token`
- **Full backfill** on initial connect -- sync all accessible content, no time limit
- On webhook update: **full page re-sync** (re-fetch entire page content + regenerate embedding)
- No incremental diffing -- Notion's API doesn't expose diffs, full replace is simpler and reliable
- Sync runs as background task, returns 202 immediately (existing pattern)

### Dashboard UI
- **New integration card** on existing integrations page (alongside Linear, Slack, GitHub, Fathom)
- Card shows: Notion logo, connected/disconnected status, **page count + last sync timestamp** (e.g., "Connected - 12 pages synced")
- **Re-sync button** on card for manual full re-import
- "Manage access" link redirects to Notion's integration settings page
- Connect/disconnect actions follow existing pattern

### Claude's Discretion
- Database schema design (new tables or extend existing ones)
- Notion block-to-markdown conversion approach (library vs custom)
- Webhook subscription management (create on connect, delete on disconnect)
- Rate limit handling for Notion API during backfill
- Error handling and retry strategy for API calls
- Notion API version to target (2025-09-03 is latest with multi-source database support)

</decisions>

<specifics>
## Specific Ideas

- Follow the exact same integration pattern as Linear/Slack/GitHub: OAuth router, service module, webhook handler, Vault token storage
- Notion's OAuth returns `workspace_id` and `workspace_name` in token response -- store these for display
- Notion API uses `Authorization: Bearer {token}` header
- Webhook setup requires SSL endpoint + verification flow via Notion dashboard (not API-created)
- `page.content_updated` events are aggregated (~1 min delay) -- not instant like Linear webhooks
- Notion's refresh tokens work: "Refreshing an access token will generate a new access token and a new refresh token"
