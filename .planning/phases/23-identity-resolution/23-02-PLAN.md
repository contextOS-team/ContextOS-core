    1. Add `"rapidfuzz>=3.0"` to `backend/pyproject.toml` dependencies list and install: `cd backend && pip install rapidfuzz`

    2. Add roster fetch functions to `backend/src/services/identity_resolution.py`:

       `async def fetch_linear_roster(session, workspace_id, user_id, settings) -> list[dict]`:
       - Use LinearGraphQLClient with access token from get_valid_access_token
       - GraphQL query: `users(first: 50, after: $after) { pageInfo { hasNextPage endCursor } nodes { id name displayName email active } }`
       - Use fetch_all_pages with connection_path=["users"]
       - Filter: skip users where active=False
       - Return list of {"platform_user_id": id, "display_name": displayName or name, "email": email}

       `async def fetch_slack_roster(session, workspace_id) -> list[dict]`:
       - Use get_bot_token for auth
       - GET https://slack.com/api/users.list with limit=200, cursor-based pagination
       - Skip bots (is_bot=True) and deleted users (deleted=True)
       - Extract email from profile.email (may be None without users:read.email scope)
       - Return list of {"platform_user_id": member.id, "display_name": profile.real_name or member.name, "email": email}

       `async def fetch_github_roster(session, workspace_id, settings) -> list[dict]`:
       - Use get_installation_token for auth
       - Get selected repos from get_cached_repos
       - For each repo: GET /repos/{full_name}/collaborators?per_page=100 with Link header pagination
       - Deduplicate by login across repos using seen_logins set
       - For each unique login: attempt GET /users/{login} to get public email (may be None)
       - Return list of {"platform_user_id": login, "display_name": login, "email": email}
       - Use create_github_client, github_headers, parse_link_next, check_rate_limit from github_common

       `async def upsert_identity_mapping(session, workspace_id, email, platform, platform_user_id, display_name) -> IdentityMapping`:
       - INSERT with ON CONFLICT (workspace_id, platform, platform_user_id) DO UPDATE SET email, display_name, deleted_at=None, updated_at=now()
       - Use pg_insert pattern from graph_ops (same ON CONFLICT pattern)

       `async def seed_roster(session, workspace_id, platform, members: list[dict]) -> int`:
       - For each member in members: call upsert_identity_mapping
       - After all members upserted: call resolve_by_email(session, workspace_id)
       - Then call find_fuzzy_candidates(session, workspace_id)
       - Return count of members seeded
       - Log progress: "Seeded {count} {platform} members for workspace {workspace_id}"

    3. Add fuzzy name matching to `backend/src/services/identity_resolution.py`:

       `def compute_name_similarity(name_a: str, name_b: str) -> float`:
       - Use `rapidfuzz.fuzz.token_sort_ratio` with score_cutoff=80
       - Normalize: lowercase + strip before comparison
       - Returns 0.0-100.0 score (0.0 if below cutoff)

       `def build_confidence_score(name_score: float) -> float`:
       - Normalize 80-100 range to 0.5-0.9 (never 1.0 for name-only matching)
       - Cap at 0.9

       `async def find_fuzzy_candidates(session, workspace_id) -> int`:
       - Query all canonical Person nodes in this workspace (properties->>'canonical' = 'true')
       - For each pair of canonical Person nodes with different canonical_person_ids:
         Compare display names (from identity_mappings linked to each canonical)
       - If compute_name_similarity >= 80: create candidate same_as edge between the two canonical nodes with properties={"status": "candidate", "confidence": build_confidence_score(score), "match_type": "fuzzy_name"}
       - Use upsert_edge to avoid duplicates
       - Return count of candidate edges created
       - IMPORTANT: Never auto-merge. Only create candidate edges per user locked decision.

    4. Write tests for all behaviors listed above. Mock external API calls (httpx, LinearGraphQLClient). Mock database session for upsert/query operations. Use pytest-asyncio for async tests.
