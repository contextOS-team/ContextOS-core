<objective>
Replace the avatar-only top-nav chrome with the unified cluster spec'd in CONTEXT §8: sync indicator (idle / syncing / error) + progress bar + click target opening an integration drawer + restyled avatar puck. The cluster lives in a new `chrome/` directory; `sidebar.tsx` becomes a thin re-export shim so other dashboard pages keep their existing top nav with the new chrome under it.

**Error-state contract (revised after checker Blocker 2):** the error state is driven SOLELY by inspecting `metadata.error` on `sync_completed` events. There is NO `sync_failed` event_type — the activity_events CHECK constraint (supabase/migrations/00031_activity_event_types.sql lines 18-28, refined by 00033_messages_digest_event_type.sql lines 17-28) does NOT include it, and `grep -rn sync_failed supabase/migrations/ backend/` returns zero matches. Per CONTEXT.md §1 ("a redesign, not a backend-extension"), this plan does NOT add a new migration to introduce `sync_failed`. Instead, the existing `sync_completed` event carries `metadata.error: string` when a sync fails — this is the single error signal the chrome subscribes to.

Purpose: the chrome cluster is independent of the pulse layout work in 41-02 — they share no files. This plan can run parallel with 41-01 (wave 1) and merge before 41-02 ships. The chrome cluster also enforces the "mint = brand only" rule (CONTEXT §6) by repainting the avatar away from `bg-primary/10 text-primary`, and lives in `dashboard/layout.tsx` so it appears on every dashboard subroute (not gated to the `.pulse-surface` scope).

Output: 5 new files in `chrome/`, sidebar.tsx refactored, 3 unit/render test files for `useSyncState` + SyncIndicator drawer wiring + cross-subroute rendering.
</objective>
