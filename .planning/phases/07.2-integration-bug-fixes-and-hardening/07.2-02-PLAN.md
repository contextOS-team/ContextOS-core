**2. Fix LLM client operator precedence (llm_client.py:106-108):**

Change lines 106-108 from:
```python
prompt_tokens = usage.prompt_token_count or 0 if usage else 0
completion_tokens = usage.candidates_token_count or 0 if usage else 0
total_tokens = usage.total_token_count or 0 if usage else 0
```
To:
```python
prompt_tokens = (usage.prompt_token_count or 0) if usage else 0
completion_tokens = (usage.candidates_token_count or 0) if usage else 0
total_tokens = (usage.total_token_count or 0) if usage else 0
```

**Why:** Python operator precedence makes `a or b if c else d` parse as `a or (b if c else d)`. When `usage` is None, Python evaluates `usage.prompt_token_count` first (before `or`), which raises `AttributeError: 'NoneType' object has no attribute 'prompt_token_count'`. The parenthesized form correctly checks `usage` first via the ternary.

**1. Add try-catch to disconnect handlers (page.tsx:81-124):**

Replace the four disconnect handlers:

```typescript
async function handleDisconnectLinear() {
  try {
    await disconnectLinear()
  } catch (err) {
    setError(
      err instanceof Error ? err.message : 'Failed to disconnect Linear'
    )
  }
  await fetchStatuses()
}

async function handleDisconnectSlack() {
  try {
    await disconnectSlack()
  } catch (err) {
    setError(
      err instanceof Error ? err.message : 'Failed to disconnect Slack'
    )
  }
  await fetchStatuses()
}

async function handleDisconnectFathom() {
  try {
    await disconnectFathom()
  } catch (err) {
    setError(
      err instanceof Error ? err.message : 'Failed to disconnect Fathom'
    )
  }
  await fetchStatuses()
}

async function handleDisconnectGithub() {
  try {
    await disconnectGithub()
  } catch (err) {
    setError(
      err instanceof Error ? err.message : 'Failed to disconnect GitHub'
    )
  }
  await fetchStatuses()
}
```

**Why:** Without try-catch, a network error during disconnect throws an unhandled promise rejection, and `fetchStatuses()` never runs. With try-catch, the error is shown to the user AND statuses refresh regardless (the `fetchStatuses()` is OUTSIDE the try-catch so it always runs, even after an error -- the user sees the error AND the page refreshes to show current state).
