**Slack OAuth service (backend/src/services/slack_oauth.py):**
Mirror the Linear OAuth pattern from `linear_oauth.py` but for Slack OAuth2 V2:

1. `_sign_state(workspace_id, secret)` and `_verify_state(state, secret)` -- reuse HMAC-SHA256 signed state pattern using SLACK_CLIENT_SECRET.

2. `build_auth_url(state, settings)` -- Build Slack OAuth V2 authorization URL:
   - URL: `https://slack.com/oauth/v2/authorize`
   - Params: client_id, redirect_uri, scope (bot scopes: `channels:read,channels:history,groups:read,groups:history,users:read`), user_scope (empty string for now -- we only need bot token), state
   - Per user decision: both bot and user token scopes. For v1, bot scopes are sufficient for reading channel messages and user info.

3. `exchange_code(code, session, workspace_id, user_id, settings)`:
   - POST to `https://slack.com/api/oauth.v2.access` with client_id, client_secret, code, redirect_uri
   - Extract `access_token` from response (at `response["access_token"]` for bot token)
   - Extract `team.id` and `team.name` from response for external_id
   - Store bot token in Vault using existing vault.store_token (name: `slack_{workspace_id}_bot_access`)
   - Upsert OAuthToken with provider="slack" (same pattern as linear_oauth.py)
   - Upsert WorkspaceIntegration with provider="slack", external_id=team.id, status="connected"
   - Note: Slack bot tokens do NOT expire and do NOT have refresh tokens. Set token_expires_at=None.

4. `disconnect(session, workspace_id, user_id)`:
   - Soft-delete OAuthToken for provider="slack"
   - Delete Vault secret
   - Mark WorkspaceIntegration as disconnected
   - Same pattern as Linear disconnect.

5. `get_bot_token(session, workspace_id)`:
   - Read bot token from Vault. Simple read since Slack bot tokens don't expire.
   - Raise OAuthError if no token found.

Define `class SlackOAuthError(Exception)` for Slack-specific errors.

**Slack Events service (backend/src/services/slack_events.py):**

1. `verify_signature(signing_secret, timestamp, body, signature)`:
   - Reuse HMAC-SHA256 verification pattern from webhook verification (02-03).
   - Slack format: `v0={hmac_sha256(signing_secret, "v0:{timestamp}:{body}")}`
   - Compare using `hmac.compare_digest` for timing safety.
   - Also check timestamp is within 5 minutes (Slack replay protection).

2. `process_event(event_payload, workspace_id, session)`:
   - Dispatch based on `event.type`:
     - `message` (with no subtype or subtype `file_share`): call `_handle_message`
     - `message` with subtype `message_changed`: call `_handle_message_edit`
     - `message` with subtype `message_deleted`: call `_handle_message_delete`
     - Ignore other subtypes (channel_join, channel_leave, channel_topic, etc. per user decision)

3. `_should_filter(event)` -> bool:
   - Return True (filter out) if:
     - `bot_id` is present in event (bot message)
     - `subtype` is one of: `bot_message`, `channel_join`, `channel_leave`, `channel_topic`, `channel_purpose`, `channel_name` (system messages)
     - `text` length < 10 characters
   - Return False otherwise (message should be stored)

4. `_handle_message(event, workspace_id, session)`:
   - If `_should_filter(event)` returns True, skip silently.
   - Check if channel_id is in the monitored channels list (query workspace_integrations config JSONB for `selected_channels` array). If not monitored, skip.
   - Determine thread relationship:
     - If `thread_ts` exists and `thread_ts != ts`: this is a reply. Set is_thread_reply=True, parent_ts=thread_ts.
     - If `thread_ts` exists and `thread_ts == ts`: this is a thread parent. Set thread_ts=thread_ts, is_thread_reply=False.
     - If no `thread_ts`: regular message.
   - Upsert SlackMessage using PostgreSQL `insert().on_conflict_do_update()` on the unique constraint (workspace_id, channel_id, slack_ts). Store:
     - slack_ts from `event.ts`
     - channel_id from `event.channel`
     - user_id from `event.user` (Slack user ID)
     - user_name: resolve from event if available, or store None (can be enriched later)
     - text from `event.text`
     - thread_ts, parent_ts, is_thread_reply as computed above
     - slack_created_at: convert `event.ts` (Unix timestamp string like "1234567890.123456") to datetime
     - raw_data: store the full event dict
   - Queue embedding generation via the stub (same pattern as linear webhook: `import src.services.embedding as embedding; await embedding.queue_embedding_generation(...)` with source_type="slack_message").

5. `_handle_message_edit(event, workspace_id, session)`:
   - Extract the edited message from `event.message` (Slack puts the new version there).
   - Find existing SlackMessage by workspace_id + channel_id + slack_ts (using event.message.ts).
   - Overwrite `text` with new text, update `raw_data`. Per user decision: overwrite stored text with latest version.
   - Queue re-embedding if text changed.

6. `_handle_message_delete(event, workspace_id, session)`:
   - Find existing SlackMessage by workspace_id + channel_id + event.previous_message.ts.
   - Set `deleted_at = now()`. Per user decision: soft-delete, context generation skips deleted messages.

**Slack router (backend/src/routers/slack.py):**

Create router with prefix `/api/slack`.

1. `GET /api/slack/connect` -- requires auth (get_current_user + get_current_workspace).
   - Build signed state, return auth URL redirect. Same pattern as linear router.

2. `GET /api/slack/callback` -- OAuth callback (no auth required, state parameter carries workspace_id).
   - Verify state, exchange code, return success response. Same pattern as linear callback.

3. `POST /api/slack/disconnect` -- requires auth.
   - Call slack_oauth.disconnect, return success. Same pattern as linear disconnect.

4. `GET /api/slack/status` -- requires auth.
   - Query WorkspaceIntegration for provider="slack", return status. Same pattern as linear status.

5. `POST /api/slack/events` -- Slack Events API endpoint (NO auth -- Slack sends events here).
   - Read raw body bytes and headers (X-Slack-Request-Timestamp, X-Slack-Signature).
   - Verify signature using slack_events.verify_signature. Return 401 on failure.
   - Handle URL verification challenge: if `payload.type == "url_verification"`, return `{"challenge": payload.challenge}`. This is required by Slack during event subscription setup.
   - For `event_callback` type: look up workspace by team_id (from payload.team_id matching workspace_integrations.external_id where provider="slack"). Delegate event processing to BackgroundTasks (same pattern as linear webhook -- return 200 immediately, process in background). Call `slack_events.process_event`.
   - Return 200 OK immediately (Slack expects fast response to avoid retries).
   - Use `import src.config as config_module` pattern for settings access (per 02-03 decision for reliable test patching).
