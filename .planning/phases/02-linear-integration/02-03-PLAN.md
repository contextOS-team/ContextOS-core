  <action>
    **Webhook router (backend/src/routers/webhooks.py):**
    Create an APIRouter with prefix="/api/webhooks", tags=["webhooks"].

    Endpoint:
    - `POST /api/webhooks/linear` -- NOT protected by JWT (webhooks come from Linear, not authenticated users). This endpoint must:

    1. **Read raw body**: Use `request.body()` to get the raw bytes. This is critical -- HMAC must be computed on the exact bytes Linear sent, not a parsed/re-serialized version.

    2. **Verify HMAC-SHA256 signature**: Read the `Linear-Signature` header (Linear sends this; NOTE: check Linear's actual webhook docs -- the header might be `linear-signature` or `x-linear-signature`). Compute `hmac.new(webhook_secret.encode(), raw_body, hashlib.sha256).hexdigest()`. Compare with `hmac.compare_digest()` for timing-safe comparison. Return 400 on mismatch with `{"error": "Invalid signature"}`.

    3. **Check idempotency**: Parse the JSON body, extract delivery ID. Linear webhook payloads include a unique delivery identifier (check actual Linear webhook format -- may be in headers as `Linear-Delivery` or in the payload). Query `webhook_deliveries` table for this delivery_id. If exists, return 200 immediately (already processed). If not, insert and continue processing.

    4. **Extract event type**: Linear webhooks include `action` (e.g., "create", "update", "remove") and `type` (e.g., "Issue", "Comment"). Parse these.

    5. **Determine workspace**: Look up which workspace this webhook belongs to by matching the organization ID from the payload against workspace_integrations.external_id where provider="linear".

    6. **Delegate to service**: Call `linear_webhook.process_webhook_event()` as a FastAPI background task. Return 200 immediately (Linear expects fast responses to avoid retries).

    **Linear webhook payload reference:**
    Linear sends webhooks as POST with JSON body:
    ```json
    {
      "action": "create|update|remove",
      "type": "Issue|Comment|IssueLabel|...",
      "data": { ...entity data... },
      "url": "https://linear.app/...",
      "createdAt": "2024-...",
      "organizationId": "org-uuid"
    }
    ```
    The signature header is `Linear-Signature` (SHA256 HMAC of the raw body).
    Linear does NOT send a delivery ID in headers -- use a combination hash of `action + type + data.id + data.updatedAt` as a synthetic delivery ID for idempotency.

    **Register router in main.py:**
    Import and include the webhooks router: `app.include_router(webhooks_router)`.

    **Webhook event processor (backend/src/services/linear_webhook.py):**
    Implements event-specific processing logic. Per user decisions: re-embed only on content changes, store events for non-synced teams without embedding, no Phase 4 triggers.

    Functions:
    1. `async process_webhook_event(session: AsyncSession, workspace_id: UUID, event: dict) -> None` -- Main dispatcher. Routes based on `event["type"]` and `event["action"]`:
       - `Issue` + `create` -> `handle_issue_create()`
       - `Issue` + `update` -> `handle_issue_update()`
       - `Issue` + `remove` -> `handle_issue_remove()`
       - `Comment` + `create` -> `handle_comment_create()`
       - `Comment` + `update` -> `handle_comment_update()`
       - `Comment` + `remove` -> `handle_comment_remove()`
       - Other types: log and ignore (future extensibility)

    2. `async handle_issue_create(session, workspace_id, data) -> None`:
       - Check if the issue's team is in synced_teams (read from workspace_integrations.config). Per user decision: if team is NOT in synced teams, store raw_data in linear_tickets but do NOT generate embeddings.
       - Upsert into linear_tickets using `insert().on_conflict_do_update()`.
       - If team IS synced, call `embedding.queue_embedding_generation()` with source_type="linear_ticket".

    3. `async handle_issue_update(session, workspace_id, data) -> None`:
       - Upsert ticket data.
       - Per user decision: re-embed ONLY on content changes. Detect content change by comparing title and description against the existing row. If only state/assignee/labels/priority changed, update metadata columns but skip re-embedding.
       - Implementation: SELECT existing ticket by linear_id, compare title and description. If different, queue embedding. If same, skip.
       - Update all metadata fields regardless (state, assignee, labels, etc.)

    4. `async handle_issue_remove(session, workspace_id, data) -> None`:
       - Soft-delete the linear_ticket (set deleted_at = now()).
       - Soft-delete associated embeddings (set deleted_at on embeddings where source_type="linear_ticket" and source_id matches).

    5. `async handle_comment_create(session, workspace_id, data) -> None`:
       - Find the parent ticket by linear issue ID from the comment data.
       - Upsert into linear_comments.
       - Per user decision: comments are content changes -> queue re-embedding of the TICKET (not the comment itself, since embeddings are per-ticket with comment context included). Actually, the embeddings table supports source_type "linear_comment", so queue embedding for the comment separately.

    6. `async handle_comment_update(session, workspace_id, data) -> None` -- Same as create (upsert + re-embed).

    7. `async handle_comment_remove(session, workspace_id, data) -> None` -- Soft-delete the comment.

    8. `def is_content_change(existing_ticket: LinearTicket, new_data: dict) -> bool` -- Helper that compares title and description. Returns True if either changed.
