    Create `backend/src/services/dashboard_resurfaced.py` with `async def get_resurfaced_items(session, workspace_id) -> list[dict]`:

    Per research recommendation, use heuristic keyword matching for v1 (not LLM -- deterministic, fast, free). The endpoint can be swapped to LLM later without frontend changes.

    Decision-like keyword patterns to match against slack_messages.text:
    - "we should", "we need to", "let's", "need to", "should we", "what if we", "plan to", "going to", "migrate to", "switch to", "consider", "proposal", "action item", "todo", "follow up"

    Query logic:
    1. Query `slack_messages` WHERE workspace_id matches AND deleted_at IS NULL AND slack_created_at > (now - 14 days) AND text ILIKE any of the keyword patterns.
    2. For each matched message, check if there's a `linear_tickets` or `jira_issues` record with a title containing similar keywords (simple substring overlap check). This is the "no ticket created" filter.
    3. Actually, simpler approach: just check if the message's text does NOT appear as a substring in any linear_ticket title in the workspace. Use a NOT EXISTS subquery.
    4. Limit to 5 results, ordered by slack_created_at DESC.
    5. Return: [{id, text (truncated to 200 chars), channel_name, user_name, created_at, type: 'resurfaced'}].

    Implementation detail: Use SQLAlchemy `or_()` with multiple `SlackMessage.text.ilike(f'%{keyword}%')` conditions. For the "no ticket" filter, use a simple approach: exclude messages where any LinearTicket in the workspace was created AFTER the message (suggesting it may have been acted on). This is imperfect but avoids expensive cross-matching.
