# Phase 39.1 Gap Closure Summary

**Extended the existing user-token poller (Plan 39-02) to cover channels, not just DMs, since bot-invite permissions for channel webhook ingestion were blocked. Ships as an inline gap closure on top of the Phase 39 plans -- phase checkpoint remains awaiting human verify.**

6. `[this commit]` docs(39.1): document user-token channel polling gap closure

## Why (context)

During the Plan 39-04 human-verify checkpoint, E2E verification surfaced
that the Slack bot doesn't receive channel events because the
`conversations.join` auto-join code (commit d96b944 on branch
`fix/slack-channel-selection`) was never merged to `main`. Bot-invite
permissions from the CTO are blocked for rollout.

Pivot: the user token the installer grants during OAuth can already
read every channel they're a member of -- no bot `/invite` required.
Plan 39-02's poller already handles rate limits, pagination, upsert
idempotency, and SET-clause parity. Extending it to channels is a
low-risk scope tweak.

## Trade-offs

- **Duplicate ingestion (bot webhook + user poll)**: safe because
  `SlackMessage` upsert is idempotent on `uq_slack_msg =
  (workspace_id, channel_id, ts)`. Plan 39-02 already enforces
  SET-clause parity at runtime via `inspect.getsource()` assertion in
  Test F. No silent data corruption risk.
- **Rate limits**: `conversations.history` caps at 1 rpm for
  non-Marketplace apps on a user token. Acceptable for small
  workspaces (our current user base). 429 handling already implemented
  in `_slack_get` (single retry honoring Retry-After).
- **Coverage scope**: user token only sees channels the installer is
  already a member of. If the installer isn't in a channel, neither
  the bot webhook path (not invited) nor the user-poll path ingests
  it. For full coverage the installer must join relevant channels.
- **Config key naming**: `include_dms` / `dms_first_enabled_at` /
  `dms_backfill_done` now semantically govern all user-token polling,
  not just DMs. Names retained for roundtrip safety with Plan 39-01's
  existing integration.config shape. Documented in module docstring.
