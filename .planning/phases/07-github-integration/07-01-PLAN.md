**OAuth Service (backend/src/services/github_oauth.py):**
GitHub App OAuth uses a different flow than regular OAuth2:
1. User is redirected to `https://github.com/apps/{APP_SLUG}/installations/new` to install the app
2. After installation, GitHub redirects to callback URL with `installation_id` and `setup_action` params
3. Backend exchanges installation_id for an installation access token via GitHub API

Implement functions following the pattern from linear_oauth.py:
- `build_install_url(settings)` -> str: Return the GitHub App installation URL. Use the pattern `https://github.com/apps/{app_slug}/installations/new` where app_slug can be derived from the GitHub App name, OR use a simpler approach: redirect to `https://github.com/settings/installations/{GITHUB_APP_ID}`. For simplicity, use the standard GitHub App install flow: `https://github.com/apps/{APP_SLUG}/installations/new?state={hmac_signed_state}`. Since we may not have the slug, use the alternate flow: construct the OAuth authorization URL `https://github.com/login/oauth/authorize?client_id={CLIENT_ID}&redirect_uri={REDIRECT_URI}&state={STATE}` -- this is the standard OAuth2 flow that GitHub Apps also support for user authorization. The installation is done separately by the user.

  Actually, per the CONTEXT.md decision "Use GitHub App installation (org-level)", use the proper GitHub App installation flow:
  - Redirect URL: `https://github.com/apps/{app_slug}/installations/new?state={signed_state}`
  - Add GITHUB_APP_SLUG to Settings (the app slug from the GitHub App URL)
  - State is HMAC-SHA256 signed with GITHUB_CLIENT_SECRET (same pattern as Linear)

- `handle_callback(installation_id, setup_action, state, workspace_id, user_id, session, settings)`:
  1. Verify HMAC state signature
  2. Generate installation access token via POST https://api.github.com/app/installations/{installation_id}/access_tokens (authenticated with JWT signed by the App private key)
  3. Store installation_id in OAuthToken.metadata_ JSONB
  4. Store the installation access token in Vault (key: `github_{workspace_id}_access_token`)
  5. Upsert WorkspaceIntegration (provider="github", status="connected", external_id from installation account)
  6. Note: Installation access tokens expire after 1 hour, so token refresh will be needed before API calls

- `get_installation_token(workspace_id, session, settings)`:
  1. Read token from Vault
  2. Check if expired (installation tokens last 1 hour)
  3. If expired, generate new one using the App JWT + POST to installations/{id}/access_tokens
  4. Store new token in Vault, return it
  5. Use the GitHub App private key to create a JWT (iat, exp=10min, iss=APP_ID) signed with RS256

- `disconnect(workspace_id, user_id, session, settings)`: Soft-delete OAuthToken, delete Vault token, update WorkspaceIntegration status

- `get_status(workspace_id, session)`: Query WorkspaceIntegration for provider="github"

Use httpx for all GitHub API calls (consistent with project pattern). For JWT signing, use python-jose (already in deps) with RS256 algorithm.
