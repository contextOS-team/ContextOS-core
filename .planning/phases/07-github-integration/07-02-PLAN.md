**Repo Service (backend/src/services/github_repos.py):**
Follow the exact pattern from slack_channels.py (channel listing/selection):

- `list_repos(workspace_id, session, settings)`:
  1. Get installation token via github_oauth.get_installation_token()
  2. Call GitHub API: GET /installation/repositories (paginated, per_page=100)
  3. Extract: full_name, name, private, description, default_branch, language
  4. Cache list in workspace_integrations.config JSONB under `available_repos` key
  5. Return list of repo dicts

- `get_cached_repos(workspace_id, session)`:
  Read from workspace_integrations.config.available_repos. Return empty list if not cached.

- `refresh_repos(workspace_id, session, settings)`:
  Same as list_repos but forces fresh API call (like Slack channel refresh pattern).

- `save_selected_repos(workspace_id, repo_full_names, session)`:
  1. Validate repo_full_names against available_repos cache
  2. Store in workspace_integrations.config.selected_repos (list of full_name strings)
  3. Return saved selection

- `is_repo_monitored(workspace_id, repo_full_name, session)`:
  Check if repo_full_name is in config.selected_repos. If no selected_repos configured, return False (unlike Slack which defaults to all -- per decision "new repos are NOT auto-monitored").

Use httpx.AsyncClient for GitHub API calls. Set headers: Authorization: token {installation_token}, Accept: application/vnd.github+json, X-GitHub-Api-Version: 2022-11-28.

Handle pagination: GitHub uses Link header with rel="next". Parse the Link header to get the next page URL. Continue fetching until no next link.

**Router additions (backend/src/routers/github.py):**
Add to existing github router (from Plan 01):
- GET /api/github/repos -> get_cached_repos (read from cache)
- POST /api/github/repos/refresh -> refresh_repos (fresh from GitHub API)
- POST /api/github/repos/select -> save_selected_repos (body: { repo_full_names: string[] })

All endpoints require auth via Depends(get_current_user).

**PR-to-Linear Linking (backend/src/services/github_linking.py):**

- `extract_linear_issue_id(branch_name, team_keys)`:
  1. Parse branch name for Linear issue pattern: `{prefix}/{TEAM_KEY}-{NUMBER}` or `{TEAM_KEY}-{NUMBER}-{description}`
  2. team_keys is a list of known Linear team keys (auto-detected from connected Linear workspace)
  3. Use regex: search for pattern matching any team key followed by hyphen and digits
  4. Return the matched issue identifier (e.g., "ENG-123") or None if no match
  5. Examples:
     - "feat/ENG-123-add-auth" -> "ENG-123"
     - "ENG-123-add-auth" -> "ENG-123"
     - "bugfix/PROJ-456" -> "PROJ-456"
     - "my-feature-branch" -> None (stored as unlinked per user decision)

- `get_linear_team_keys(workspace_id, session)`:
  Query linear_tickets table for distinct team prefixes. Extract the prefix part from identifier column (e.g., "ENG" from "ENG-123"). Return as list of strings.

- `link_pr_to_ticket(pr, workspace_id, session)`:
  1. Call extract_linear_issue_id with PR branch_name and known team_keys
  2. If match found, query linear_tickets for matching identifier in this workspace
  3. If ticket found, update pr.linear_ticket_id = ticket.id
  4. If no match or ticket not found, leave pr.linear_ticket_id as None (unlinked per user decision)

**PR Sync Service (backend/src/services/github_sync.py):**
Follow the pattern from linear_sync.py:

- `sync_repos(workspace_id, selected_repos, session, settings, background_tasks)`:
  1. Process repos **sequentially** (per user decision: "sequential sync with rate limit awareness")
  2. For each repo, call sync_single_repo
  3. Update per-repo sync status in workspace_integrations.config JSONB:
     ```json
     { "repo_sync_status": { "org/repo": { "status": "syncing", "synced": 12, "total": 45 } } }
     ```
  4. On sync failure: mark repo as "error", keep partial data, log the error

- `sync_single_repo(workspace_id, repo_full_name, session, settings)`:
  1. Get installation token via github_oauth.get_installation_token()
  2. Fetch PRs via GET /repos/{owner}/{repo}/pulls?state=all&sort=updated&direction=desc&per_page=100
  3. **Backfill window: 60 days** (per user decision). Stop pagination when PR updated_at is older than 60 days.
  4. For each PR:
     a. Also fetch reviews via GET /repos/{owner}/{repo}/pulls/{number}/reviews
     b. Upsert GithubPullRequest (on conflict: workspace_id + github_id)
     c. Upsert GithubReview records (on conflict: workspace_id + github_id)
     d. Call link_pr_to_ticket to attempt Linear linking
  5. **Filter known bot accounts**: skip PRs authored by dependabot[bot], renovate[bot], github-actions[bot] (per user decision)
  6. **Include drafts**: ingest all PRs including draft state (per user decision)
  7. Monitor GitHub API rate limit: check X-RateLimit-Remaining header. If < 100, sleep until X-RateLimit-Reset timestamp.
  8. Update per-repo progress in config JSONB after each page

- Queue embedding generation stub (same pattern as linear_sync.py) for PR description content.
