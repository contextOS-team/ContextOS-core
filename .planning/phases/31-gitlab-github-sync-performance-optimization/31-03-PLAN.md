<objective>
Make code indexing clone and parse multiple repositories concurrently instead of sequentially, with configurable parallelism and per-repo timeouts.

Purpose: For workspaces with 5+ monitored repos, sequential indexing means each repo waits for the previous to finish cloning, parsing, and upserting. Concurrent indexing with a semaphore (default 3 parallel repos) reduces total indexing time by 2-3x while respecting system resources.

Output: Refactored `index_workspace_repos` and `index_gitlab_workspace_repos` with asyncio.gather-based concurrent repo processing.
</objective>

Refactor both `index_workspace_repos` and `index_gitlab_workspace_repos` in `code_indexer.py`:

1. **Configurable concurrency constant:**
   - Add `MAX_CONCURRENT_CLONES = 3` constant near the top (after existing constants)
   - Add `REPO_INDEX_TIMEOUT = 600` constant (10 minutes per repo -- longer than sync because cloning is I/O heavy)

2. **Refactor index_workspace_repos (GitHub):**
   - Add `import asyncio` if not already present (it IS already imported for create_subprocess_exec)
   - Create an inner async function `_index_one(idx, repo)` that:
     a. Updates progress via `_update_index_status(workspace_id, "indexing", provider="github", progress=idx, total=total, current_repo=full_name)`
     b. Uses `async with asyncio.timeout(REPO_INDEX_TIMEOUT):` to wrap the indexing
     c. Creates its own DB session via `async with async_session() as task_session:` (import from `src.db`) -- this avoids SQLAlchemy session sharing across concurrent coroutines (research Pitfall 1, 4)
     d. Calls `index_repo(workspace_id, full_name, task_session, settings, provider="github")`
     e. Calls `await task_session.commit()` on success
     f. On any exception (including TimeoutError): logs, rolls back, returns error result dict
     g. Returns the summary dict
   - Create `_clone_semaphore = asyncio.Semaphore(MAX_CONCURRENT_CLONES)` inside the function
   - Wrap `_index_one` body with `async with _clone_semaphore:`
   - Replace the sequential `for idx, repo in enumerate(monitored_repos)` loop with:
     ```python
     tasks = [_index_one(idx, repo) for idx, repo in enumerate(monitored_repos)]
     results = await asyncio.gather(*tasks, return_exceptions=True)
     ```
   - After gather, filter results: convert any Exception results to error dicts, collect successful dicts
   - Remove the old `session.commit()` / `session.rollback()` calls (each task manages its own session now)
   - The outer `session` parameter is still accepted but only used for reading monitored repos (before the gather). The caller's session is not used for writes.

3. **Refactor index_gitlab_workspace_repos (GitLab):**
   - Apply the exact same pattern as GitHub above, but:
     a. Use `provider="gitlab"` in `_update_index_status` and `index_repo` calls
     b. Add `await ensure_valid_token(task_session, workspace_id, settings)` before `index_repo` inside each task (GitLab tokens expire in 2 hours -- per Phase 28 decision)
     c. Name the inner function `_index_one_gitlab(idx, repo)` for clarity

4. **Import addition:** Add `from src.db import async_session` at the top.

5. **Progress update after gather:** After `asyncio.gather` completes, update progress to show completion:
   ```python
   if total > 0:
       await _update_index_status(workspace_id, "indexing", provider=..., progress=total, total=total, current_repo=None)
   ```

Key constraints:
- Each concurrent task MUST use its own `async_session()` -- never share the caller's session

- The `_clone_semaphore` should be created inside each function (not module-level) to avoid cross-function interference
- Keep the `finally` block that resets status to "idle" on both functions
