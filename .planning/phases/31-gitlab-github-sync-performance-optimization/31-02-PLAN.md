<objective>
Optimize GitHub PR sync to fetch reviews concurrently, use incremental cursors, support state filtering, enforce per-repo timeouts, and emit granular progress.

Purpose: Eliminate the sequential per-PR review fetch bottleneck in GitHub sync. The existing `_github_semaphore(10)` already handles API concurrency -- this plan applies it to batch-fetch reviews for all PRs in a page via asyncio.gather instead of one-by-one. Incremental cursors replace the hardcoded 60-day cutoff with the persisted sync_start timestamp.

Output: Refactored `github_sync.py` with concurrent review fetching, incremental cursor persistence, state filter, per-repo timeout, and progress emission.

Refactor `github_sync.py` with the following changes:

1. **Concurrent review fetching (PERF-SYNC-01):**
   - Create `_fetch_reviews_bounded(client, token, owner, repo, pr_number)` wrapper that reuses the existing `_github_semaphore` (already imported, already Semaphore(10))
   - In `sync_single_repo`, after fetching a page of PRs, collect all non-bot PRs and batch-fetch their reviews with `asyncio.gather(*tasks, return_exceptions=True)`
   - Process results sequentially for DB writes (upsert PR, upsert reviews, link to ticket -- all sequential)
   - Handle Exception results from gather by logging warning and skipping that PR's reviews
   - Move the `_fetch_reviews` function to use the bounded wrapper pattern

2. **Incremental cursor (PERF-SYNC-02):**
   - Import `get_or_create_cursor` from `sync_adapter` (update_cursor_status already imported)
   - At the start of `sync_single_repo`, call `get_or_create_cursor(session, workspace_id, "github", repo_full_name)`
   - Record `sync_start = datetime.now(timezone.utc).replace(tzinfo=None)` BEFORE fetching
   - If `cursor.cursor_value` is not None, parse it as datetime and use it as the cutoff instead of the 60-day `cutoff` variable. GitHub has no `updated_after` URL param, so keep the existing `reached_cutoff` pattern but compare against the cursor value
   - After successful sync, call `update_cursor_status(..., cursor_value=sync_start.strftime("%Y-%m-%dT%H:%M:%SZ"))` to persist the cursor

3. **State filter (PERF-SYNC-05):**
   - Add `state_filter: str = "all"` parameter to both `sync_repos()` and `sync_single_repo()`
   - Pass state_filter through from `sync_repos` to `sync_single_repo`
   - In the PR fetch URL, use `state={state_filter}` -- GitHub accepts: all, open, closed
   - Note: GitHub uses "open" not "opened" (unlike GitLab)

4. **Per-repo timeout (PERF-SYNC-04):**
   - Add `REPO_SYNC_TIMEOUT = 300` constant (5 minutes)
   - In `sync_repos`, wrap the `sync_single_repo` call with `async with asyncio.timeout(REPO_SYNC_TIMEOUT):`
   - Catch `TimeoutError` alongside existing exceptions, log warning, set status to "timeout", and continue to next repo
   - Commit partial data on timeout

5. **Progress events (PERF-SYNC-06):**
   - The existing per-PR `_update_repo_sync_status` call inside `sync_single_repo` already emits progress. Keep it but ensure it fires per-page (after processing all PRs in a page) rather than per-PR to reduce DB writes. Move the call outside the inner for loop to after the page processing.

6. **Import additions:** Add `import asyncio` at the top. Add `get_or_create_cursor` to the sync_adapter import.

Key constraints:
- Keep all DB writes sequential (gather only for API calls)
- Use `return_exceptions=True` in all asyncio.gather calls
- Reuse existing `_github_semaphore` (don't create a new one)
- GitHub cutoff is checked client-side (compare updated_at < cursor), not via URL param
- `sync_start` timestamp for cursor (not max updated_at)
