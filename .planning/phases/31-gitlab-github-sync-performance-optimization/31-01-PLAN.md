<objective>
Optimize GitLab MR sync to fetch notes concurrently, use incremental cursors, support state filtering, enforce per-project timeouts, and emit granular progress.

Purpose: Eliminate the sequential per-MR note fetch bottleneck in GitLab sync. For a workspace with 5 projects and 100 MRs each, this reduces ~500 sequential API calls to ~100 batched concurrent calls (5 at a time), cutting sync time by 5-10x. Incremental cursors avoid re-fetching unchanged MRs on subsequent syncs.

Output: Refactored `gitlab_sync.py` with concurrent note fetching, incremental cursor persistence, state filter, per-project timeout, and progress emission.
</objective>

Refactor `gitlab_sync.py` with the following changes:

1. **Concurrent note fetching (PERF-SYNC-01):**
   - Add module-level `_NOTE_FETCH_SEMAPHORE = asyncio.Semaphore(5)` (5 concurrent note fetches, conservative for GitLab's 10 req/sec limit)
   - Create `_fetch_notes_bounded(client, token, project_id, mr_iid)` wrapper that uses the semaphore
   - In `sync_single_project`, after fetching a page of MRs, collect all non-bot MRs and batch-fetch their notes with `asyncio.gather(*tasks, return_exceptions=True)`
   - Process results sequentially for DB writes (avoid concurrent session access per research Pitfall 1)
   - Handle Exception results from gather by logging warning and skipping that MR's notes

2. **Incremental cursor (PERF-SYNC-02):**
   - At the start of `sync_single_project`, call `get_or_create_cursor(session, workspace_id, "gitlab", str(project_id))`
   - Record `sync_start = datetime.now(timezone.utc).replace(tzinfo=None)` BEFORE fetching (per research Pitfall 3 -- use sync start time, not max updated_at)
   - If `cursor.cursor_value` is not None, use it as `updated_after` instead of the 60-day cutoff
   - After successful sync, call `update_cursor_status(..., cursor_value=sync_start.strftime("%Y-%m-%dT%H:%M:%SZ"))` to persist the cursor

3. **State filter (PERF-SYNC-05):**
   - Add `state_filter: str = "all"` parameter to both `sync_projects()` and `sync_single_project()`
   - Pass state_filter through from `sync_projects` to `sync_single_project`
   - In the MR fetch URL, use `state={state_filter}` (GitLab accepts: all, opened, closed, merged)

4. **Per-project timeout (PERF-SYNC-04):**
   - Add `PROJECT_SYNC_TIMEOUT = 300` constant (5 minutes)
   - In `sync_projects`, wrap the `sync_single_project` call with `async with asyncio.timeout(PROJECT_SYNC_TIMEOUT):`
   - Catch `TimeoutError` alongside existing exceptions, log warning, set status to "timeout", and continue to next project
   - Commit partial data on timeout (the session has flushed data from within sync_single_project)

5. **Progress events (PERF-SYNC-06):**
   - In `sync_single_project`, after processing each page of MRs, call `_update_project_sync_status(session, workspace_id, project_id, "syncing", mr_count, 0)` to emit per-page progress
   - This reuses the existing `_update_project_sync_status` function

6. **Import additions:** Add `import asyncio` at the top and import `get_or_create_cursor` from `sync_adapter`.

Key constraints:
- Keep all DB writes sequential (gather only for API calls, not DB operations)
- Use `return_exceptions=True` in all asyncio.gather calls
- Semaphore value 5 for GitLab (stricter rate limits than GitHub)
- `sync_start` timestamp for cursor (not max updated_at) to handle MRs updated during sync
