<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend source metadata -> browser UI | API-provided explanation fields become visible to users. |
| source link -> browser navigation | `Open source` links may point to provider or internal source references. |
| active workspace -> rendered source rows | UI must not render mismatched workspace sources if backend ever returns them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-06-01 | Information Disclosure | source explanation UI | mitigate | Render only backend-provided active page sources; do not fetch arbitrary source paths client-side. |
| T-46-06-02 | Tampering | source explanation copy | mitigate | Treat fields as text; no HTML injection or markdown rendering inside trace metadata. |
| T-46-06-03 | Repudiation | source path disclosure | mitigate | Display source path, freshness, verification, and why-selected fields next to each source row. |
| T-46-06-04 | Information Disclosure | stale/generated labels | mitigate | Text-first labels distinguish stale and generated context from confirmed source evidence. |
| T-46-06-05 | Denial of Service | sidebar layout | mitigate | Keep disclosure bounded and hide absent metadata; no full-page loading or layout-wide animation. |
| T-46-06-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task exists in this plan; reuse existing shadcn/lucide stack. |
</threat_model>
