<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider timestamps -> ranking | Source records have different timestamp semantics and cannot be treated uniformly without policy. |
| generated context -> source grounding | Generated context may summarize evidence but is not primary source evidence. |
| selected/dropped traces -> user trust | Trace explanations affect user confidence and must not drift from ranking facts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-03-01 | Tampering | freshness matrix | mitigate | Define provider-specific timestamp policy and test unknown/stale/generated cases. |
| T-46-03-02 | Information Disclosure | ranking feature bundle | mitigate | Workspace mismatch remains a hard invalid state, not a rankable feature in selected results. |
| T-46-03-03 | Repudiation | selected/dropped explanations | mitigate | Preserve score features, graph path, freshness, verification, and suppression reasons in trace metadata. |
| T-46-03-04 | Tampering | generated context evidence | mitigate | Downrank or drop generated context when primary source evidence exists; eval case enforces this. |
| T-46-03-05 | Denial of Service | ranking feature computation | mitigate | Feature computation occurs before truncation but must stay deterministic and avoid extra model calls. |
| T-46-03-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task exists in this plan. |
</threat_model>
