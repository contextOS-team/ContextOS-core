# Phase 08.1: Dashboard Design Polish - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Elevate the existing dashboard (home page, integrations page, sidebar/nav, global styles) from AI-template aesthetic to a distinctive, polished ContextOS product. Frontend-only changes to existing components. No new pages, no backend changes, no new data fetching endpoints.

</domain>

<decisions>
## Implementation Decisions

### Visual Identity & Density
- Home page is a **hybrid monitoring dashboard with quick actions** -- status-first but with inline connect/disconnect capability
- The greeting ("Good afternoon, Daulet") stays but becomes **subtle and understated** -- not the hero element. Integration status is the hero
- Visual inspiration: blend of **Linear** (minimal, high density, serious dev tool), **Vercel** (intentional white space, monitoring feel), and **Raycast** (power tool, compact) -- ContextOS should feel like something special that takes the best from all three
- The current empty-space problem must be solved -- fill the page with useful density

### Integration Display Model
- Home page integration display: **Claude's discretion** based on critique findings (compact rows, status bar, or richer cards -- pick what eliminates the empty-space problem and maximizes scannability)
- Integrations page layout: **Claude's discretion** -- refine based on critique (better hierarchy, tighter spacing, remove fluff)
- Status indicators: **Claude's discretion** -- remove the overused green pill/pulsing dot pattern, replace with something more refined
- Card descriptions: **Claude's discretion** -- the marketing-copy descriptions ("Import issues and project context from Linear") should be eliminated or replaced with live/useful info
- **Use actual brand logos** (SVG) for Linear, Slack, GitHub, Fathom instead of generic Lucide icons. Source official or recognizable brand marks

### Sidebar & Navigation
- **Replace the sidebar with a top navigation bar** -- with only 2 nav items, the sidebar wastes 248px of horizontal space
- Top nav layout: **Claude's discretion** -- design based on the Linear/Vercel/Raycast hybrid feel
- Top nav color: **Claude's discretion** -- dark bar or light/transparent, pick what works best
- Logo: **"ContextOS" text wordmark only**, no Zap icon. Cleaner, more mature. Like how Linear just says "Linear"
- Sign out and user info must still be accessible from the nav area

### Typography & Color System
- **Switch from DM Sans to Inter** -- the standard developer tool font. Better readability, neutral, professional
- Keep JetBrains Mono for monospace elements
- Keep warm off-white page background (#fafafa-ish) -- provides natural depth layering between page and cards
- **Shift brand color from indigo to a deeper blue** -- more distinctive, more serious, less "Tailwind default indigo." Claude picks the exact hue within the deep blue family
- Integration icons use **actual brand colors/logos** (not rainbow Lucide icons)

### Claude's Discretion
- Home page content density strategy (what fills the space beyond integration status)
- Integration card information hierarchy and layout (home + integrations page)
- Status indicator design (replacing the green pill + pulsing dot)
- Top nav exact layout, color treatment, and spacing
- Specific deep blue brand color choice
- All animation and hover interaction refinements
- Loading skeleton and empty state designs

</decisions>

<specifics>
## Specific Ideas

- "Take all of them, something special" -- the dashboard should feel like a unique product, not a clone of any single reference. Draw from Linear's density, Vercel's intentional space, Raycast's power-tool feel
- Use actual SVG brand logos for integrations -- this is a strong identity move that immediately makes the dashboard look professional and real
- "ContextOS" as pure text wordmark -- mature, confident, no icon needed
- The current state reads as "AI scaffold that was never filled in" -- the #1 priority is making it feel hand-crafted and intentional
- Every pixel should communicate "we built this specifically for ContextOS" not "we used a template"

</specifics>
