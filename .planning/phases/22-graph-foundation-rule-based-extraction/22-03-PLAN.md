**Add extract_and_populate_graph() to backend/src/services/graph_extractor.py:**

This is the single entry point that all webhook handlers call. It:
1. Creates a source node for the content being processed (e.g., Ticket node for a linear_ticket, SlackThread node for a slack_message). Uses a SOURCE_TYPE_TO_ENTITY mapping: {"linear_ticket": "Ticket", "linear_comment": "Ticket", "slack_message": "SlackThread", "github_pull_request": "PR", "github_review": "PR", "notion_page": "NotionPage", "meeting_transcript": "Meeting", "meeting_segment": "Meeting", "code_chunk": "CodeChunk", "context_page": "Ticket"}
2. Calls run_extractors(content, source_type) to get extracted entities
3. For each extracted entity, calls upsert_node() to create/update the entity node (with status="unresolved" in properties if it's a dangling reference)
4. For each extracted entity, calls upsert_edge() to create the relationship from the source node to the entity node
5. Entire function is wrapped in try/except -- logs warning on failure but never raises. This is CRITICAL per CONTEXT.md: graph extraction is additive, core ingestion must never fail because of it.

Signature:
```python
async def extract_and_populate_graph(
    session: AsyncSession,
    workspace_id: UUID,
    content: str,
    source_type: str,
    source_id: UUID,
    source_name: str,
    source_external_id: str | None = None,
) -> None:
```

The source_external_id parameter is used for the source node's external_id in fingerprint computation. If not provided, falls back to str(source_id). This ensures source nodes have stable fingerprints across re-ingestion.

**backend/src/services/graph_backfill.py:**

Create a backfill script that processes all existing content to populate the graph. This makes the graph immediately useful, not just for new content.

Structure:
```python
async def backfill_graph(batch_size: int = 100) -> dict:
    """Process all existing content to populate graph nodes and edges.

    Returns dict with counts: {"tickets": N, "comments": N, "messages": N, ...}
    """
```

For each source type (linear_tickets, linear_comments, slack_messages, github_pull_requests, github_reviews, notion_pages, meeting_transcripts):
1. Query all non-deleted records with workspace_id
2. Process in batches of batch_size
3. For each record, call extract_and_populate_graph() with appropriate content, source_type, source_id, source_name
4. Commit after each batch
5. Log progress: "Backfill {source_type}: batch {N}/{total_batches}, {extracted_count} entities"

Content extraction per source type (reuse the SOURCE_TYPE_MAP logic from embedding.py):
- linear_ticket: f"{ticket.title}\n\n{ticket.description or ''}"
- linear_comment: comment.body
- slack_message: message.text
- github_pull_request: f"{pr.title}\n\n{pr.body or ''}"
- github_review: review.body
- notion_page: f"{page.title}\n\n{page.content or ''}"
- meeting_transcript: f"{transcript.title or ''}\n\n{transcript.transcript}"

Use src.db.async_session() for DB sessions (same as webhook handlers). Process order does not matter -- unresolved nodes handle forward references.

Add a `if __name__ == "__main__":` block so it can be run as `python -m src.services.graph_backfill`.
