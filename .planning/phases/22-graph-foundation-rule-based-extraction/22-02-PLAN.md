**backend/src/services/graph_extractor.py:**

Create the complete extractor system with these components:

1. **ExtractedEntity dataclass:**
   - entity_type: str (must match graph_nodes CHECK constraint values)
   - external_id: str (used with entity_type for fingerprint computation)
   - name: str (human-readable display name)
   - properties: dict (additional metadata, default_factory=dict)
   - relationship_type: str (must match graph_edges CHECK constraint values)

2. **Extractor Protocol:**
   - `def extract(self, content: str, source_type: str) -> list[ExtractedEntity]`

3. **Registry:**
   - `_EXTRACTORS: list[Extractor]` module-level list
   - `register_extractor(extractor: Extractor) -> None`
   - `run_extractors(content: str, source_type: str) -> list[ExtractedEntity]`: Iterates registry, collects results, deduplicates by (entity_type, external_id) keeping first occurrence, wraps each extractor call in try/except with logger.warning on failure

4. **Five extractors (each as a class implementing Extractor protocol):**

   a. **TicketRefExtractor**: Pattern `r'\b([A-Z]{2,10})-(\d{1,6})\b'`. Entity type: "Ticket". External ID: the full match (e.g., "ENG-123"). Relationship: "references". Deduplicate within extractor via seen set.

   b. **MentionExtractor**: Two patterns -- Slack UIDs `r'<@(U[A-Z0-9]{6,12})>'` and platform usernames `r'(?<!\S)@([a-zA-Z][a-zA-Z0-9._-]{1,38})\b'`. Entity type: "Person". External IDs: "slack:{uid}" or "username:{username}". Relationship: "mentions". Deduplicate across both patterns.

   c. **PRRefExtractor**: Two patterns -- PR numbers `r'(?<!\w)#(\d{1,6})\b'` and commit SHAs `r'\b([0-9a-f]{7,40})\b'`. For SHAs, reject if all digits (isdigit()). Entity type: "PR". External IDs: "PR:#{num}" or "commit:{sha[:7]}". Relationship: "references". Mark ambiguous PRs with properties={"status": "ambiguous"} when source_type is not github-related per RESEARCH.md open question #3.

   d. **FilePathExtractor**: Pattern matching paths with common code extensions (.ts, .tsx, .js, .jsx, .py, .rs, .go, .sql, .md, .json, .yaml, .yml, .toml, .css, .html). Entity type: "CodeChunk". External ID: "path:{matched_path}". Relationship: "references".

   e. **URLExtractor**: Only match known integration URL patterns per CONTEXT.md:
      - linear.app issue URLs -> entity_type="Ticket", extract identifier
      - github.com pull URLs -> entity_type="PR", extract repo + number
      - github.com commit URLs -> entity_type="PR", extract repo + sha
      - notion.so page URLs -> entity_type="NotionPage", extract page ID
      - slack.com archive URLs -> entity_type="SlackThread", extract channel + timestamp
      Relationship: "references". Properties include {"url": full_url, "resolved_from": "url"}.

5. **Auto-registration:** At module level, after class definitions, instantiate each extractor and call register_extractor(). This ensures extractors are active on import.

- **No LLM calls:** Verify no imports from openai, anthropic, or any LLM client (static check)

Use pytest. Each test function should be focused (test one behavior). Group by extractor class. Follow existing test file naming from the project.
