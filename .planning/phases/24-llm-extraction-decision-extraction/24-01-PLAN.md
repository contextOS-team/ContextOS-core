    - TestContentHashDedup::test_case_preservation: compute_content_hash("Hello") != compute_content_hash("hello") (case matters for content identity -- unlike RESEARCH.md which lowercases, keep case since decisions can differ by case)
  </behavior>
  <action>
    Add TestSourceValidation and TestContentHashDedup test classes to backend/tests/test_llm_extractor.py (RED phase first).

    Add to backend/src/services/llm_extractor.py:
    1. validate_extraction(result: ExtractionResult, original_content: str) -> ExtractionResult:
       - Lowercase both source_quote and original_content for comparison
       - Keep only decisions where decision.source_quote.lower() is found as substring in original_content.lower()
       - Keep only blockers where blocker.source_quote.lower() is found as substring
       - Log warning for each dropped entity with truncated quote (first 80 chars)
       - Return new ExtractionResult with only valid entities
    2. compute_content_hash(text: str) -> str:
       - Normalize whitespace: " ".join(text.strip().split())
       - SHA-256 hex digest of normalized text (do NOT lowercase -- preserve case for content identity)
       - Return 64-char hex string

    Note on case: validate_extraction does case-insensitive comparison for flexibility (LLM may adjust case in quotes), but compute_content_hash preserves case because different-cased content is semantically different content.
  </action>
